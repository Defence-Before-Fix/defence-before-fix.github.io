# Changes to the acceptance process

Changes to the acceptance process, as [ACCEPTANCE.md](../ACCEPTANCE.md) defines one under
"Changes to this process", recorded here as it describes: a line is added at the top for each
change, naming its pull request. The process is not a specification and is not versioned, and a
change to it is not tested by a cohort. Changes to the three specifications are recorded in
[CHANGELOG.md](../CHANGELOG.md).

- [Pull request #26](https://github.com/Defence-Before-Fix/defence-before-fix.github.io/pull/26): the method key's 2a says how an answer is marked when it says that the
  defect handed is fixed after some steps and, elsewhere, that every instance is swept and fixed,
  without saying which comes first. The question asks in what order, so the order is the point of
  element (2), and such an answer does not state it. The key now says that "the fix" in element
  (2) is the fix of the defect handed, that a quotation such as clause 3.4's "before fixing anything" states it, and that an answer
  putting the fix before the sweep is wrong whatever it quotes. Run 89, on the gap-terms change,
  recorded the point as open and marked it for the reader under the open-point rule. This applies
  to runs whose readers start after it merges, and changes no mark already given.
- [Pull request #22](https://github.com/Defence-Before-Fix/defence-before-fix.github.io/pull/22):
  the test is made to prove what it exists to prove, the clarity of the
  document to a cold reader, after thirty-three runs on two changes (19 to 30, 31 to 33 and 35
  to 52) in which keyed answers reached five of five and the runs still failed. Five defects in
  the process were found. Keys required elements the question never asked for (detector 2b's
  "need not remove or forbid", detector 2c's "at a version tracked together", and on pull
  request 14 method 2d's order of the kinds), so readers who answered the question as put were
  marked wrong: now each key lists, per item, the elements an answer must state, one for
  each part of the question, and the questions are reworded to ask for exactly those; anything
  else in the key only catches a wrong assertion. A passage two readers found confusing stayed
  open whilst any single reader of a later cohort named any part of its paragraph, so cleared
  passages kept coming back: now a finding is settled run by run, raised by two readers of one
  run and clear when the next names it by fewer than two. A finding landed on text the change
  never touched, so a change's cohort acted as a review of the whole document and could not
  converge: now a finding in text the change wrote or altered blocks the change, and a finding
  elsewhere is routed to `acceptance/ROUTED.md` and to a change of its own, whilst the keyed
  questions still prove the whole document on every run. Markers invented judgements the rules
  left open and later runs cited them as precedent: now an open point is marked for the reader
  and settled in this file or the key before the next run, and a run record states no judgement
  the rules do not. The rule that any miss whose reasoning quoted the document was a finding
  whatever the count is replaced by the key naming the wrong readings the text invites, which
  count against the document on one reader, every other single miss being tolerated by the
  all-but-one threshold. Question 2's instruction asks for the sentence or sentences relied on,
  since three keys rest on two. The cohort, the packet, set-aside readers, the posted sheets,
  the fuller record and the route for a process change are kept from the earlier proposal in
  pull request 13, which this change supersedes. Relative to the rules on `next`, the
  traceable-miss row is narrower and the confusion row is applied to the change rather than
  the document; both are recorded here as the reason the earlier rules could not converge, and
  neither changes a mark already given. Prompted by runs 19 to 30 on pull request 14 and runs
  31 to 33 and 35 to 52 on the defined-terms change.
