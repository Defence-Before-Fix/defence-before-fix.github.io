# sqruff

{% include tool-grades.html %}

sqruff is a SQL linter and formatter written in Rust, a fast reimplementation of SQLFluff's rules and configuration: 77 bundled rules, each with a code such as `AM04` and a dotted name such as `ambiguous.column_count`, over a parser for many dialects, with no database needed. In a pipeline it is the SQL lint and format step where SQLFluff's speed is the obstacle; it reads `.sqruff` or SQLFluff's configuration files and honours `-- noqa` comments in the same form.

## How it is conformant

sqruff runs locally on a single file, a directory or standard input, with no service and no licence tier, and prints every finding in the command's own output; it has no option that writes the report elsewhere ([CLI reference](https://github.com/quarylabs/sqruff/blob/v0.41.0/docs/reference/cli.md), ran) ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) to [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)). `sqruff -n lint d.sql` printed `L:   1 | P:   1 | AM04 | Outermost query should produce known number of columns.` with `[ambiguous.column_count]` beneath it, exit 1 (ran).

`sqruff rules` prints every rule's code, name, one-line description and groups from the binary, such as `AM04: [ambiguous.column_count] Outermost query should produce known number of columns.` With the network removed (`unshare -rn`) it listed all 77 codes, one for each rule module in the [source at the tag](https://github.com/quarylabs/sqruff/tree/v0.41.0/crates/lib/src/rules) (ran). That listing is an index whose entries are labelled with the code exactly as printed and hold a description, which meets [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) for the bundled rules under readings 11 and 12, works offline ([6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access)), and ships in the same binary as the rules ([6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together)); the description is one line, and the fuller text in the [rules reference](https://github.com/quarylabs/sqruff/blob/v0.41.0/docs/reference/rules.md) is online only. Every rule must implement `description` as a required method of the `Rule` trait ([`rules.rs`](https://github.com/quarylabs/sqruff/blob/v0.41.0/crates/lib/src/core/rules.rs)), so no release can build a rule without one, though nothing checks that it is not empty ([6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation), partial).

The `-- noqa` comments, in their line, rule-list and `disable=`/`enable=` range forms ([noqa](https://github.com/quarylabs/sqruff/blob/v0.41.0/docs/usage/noqa.md)), are switched off by `--disable-noqa` or `disable_noqa = True` in the configuration file: both restored the hidden findings, including those under `-- noqa: disable=all`, on files given by path (ran). `--disable-noqa-except` keeps a named few. `.sqruffignore` is closed by `--disregard-sqruffignores`: the run processed 0 files without it and 1 with it (ran, [ignore files](https://github.com/quarylabs/sqruff/blob/v0.41.0/docs/usage/ignore-files.md)). `warn_unused_ignores = True` reported `NOQA | WARNING: Unused noqa: 'noqa: AM04'` for a comment that hid nothing (ran).

## How it is not conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) fails. Each rule is a Rust type compiled into the binary, the CLI has no option to load one, and the project's answer to [issue 903](https://github.com/quarylabs/sqruff/issues/903), "Do you support custom rules?", closed without such a route, a later commenter noting that adding one "requires a public API to set custom rules". Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is graded on the bundled rules and is partial (reading 4): `lint` has no option that selects a rule, and the one way found to run one alone was a configuration file reading `rules = LT01`, passed with `--config`, which reported only `LT01` (ran).

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is partial. The code is not chosen as a value: the `Rule` trait's default `code` takes the Rust type name and strips its `Rule` prefix, so `RuleAM04` prints `AM04`, and no bundled rule overrides it ([`rules.rs`](https://github.com/quarylabs/sqruff/blob/v0.41.0/crates/lib/src/core/rules.rs)); that is the derivation from a class name [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) rules out (reading 5). The `name`, chosen as a string by the rule's author, is printed in the default output and as the `name` of each rule in SARIF, but `json` and `github-annotation-native` print only the code, and a SARIF result carries only `ruleId: AM04` (ran). The register grades this as it grades SQLFluff: the author-chosen identifier holds in the default output and fails in some formats. A file that does not parse is reported with `????` in the code column and `"code": null` in JSON (ran), so that finding carries no identifier at all.

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fails, for a route the documentation does not describe. A comment line beginning `-- sqruff:` or `-- sqlfluff:` sets configuration for the file it is in ([`config.rs`](https://github.com/quarylabs/sqruff/blob/v0.41.0/crates/lib/src/core/config.rs), `process_raw_file_for_config`; [`core.rs`](https://github.com/quarylabs/sqruff/blob/v0.41.0/crates/lib/src/core/linter/core.rs), `with_inline_config`), and no option refuses it. With `rules = all` configured, `sqruff lint -` reading `-- sqruff:exclude_rules:AM04` and `SELECT * FROM t;` from standard input printed no finding and exited 0, and under `--disable-noqa` standard input whose first line was `-- sqruff:disable_noqa:False` had its `-- noqa` honoured again, exit 0 (ran). The same directives had no effect on a file given by path (ran). No project rule can be written to see them, so the route can be neither switched off nor seen (reading 16), and a check that pipes SQL into sqruff, as an editor or a hook may, is open to it. No reason is asked for on a `noqa` ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)), and there is no rule over the rules ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)).

The SARIF output gives each rule a `helpUri` of the form `https://playground.quary.dev/docs/reference/rules/#ambiguouscolumn_count`, the name with its dot removed on a website, which is keyed on a transformed address and resolves nothing under reading 11; `sqruff rules AM04` is refused ("unexpected argument"), so a single code is found by searching the listing. The `NOQA` code of the unused-ignore warning is not in the listing.

Readiness is 🔴 because no bespoke rule can be written. The detector grade is 🔴 because [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) fails, structural under reading 1; [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) and [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) are partial and [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fails. sqruff declares no version of this document.

## Notes for a practitioner

sqruff cannot hold a project's own defence; put that in SQLFluff as a plugin rule, or in a pattern engine, and use sqruff for its speed on the bundled rules. Give every enforced run its files by path rather than on standard input, set `disable_noqa = True` in `.sqruff` if the project forbids suppressions, and add `warn_unused_ignores = True`. Search for `-- sqruff:` and `-- sqlfluff:` lines in the build, outside sqruff, since sqruff never reports them. Read the code column, not the name, in machine-readable output, since only the code is in every format; look a code up in `sqruff rules`. Show parse errors with `--parsing-errors` where a template makes them likely, and treat a `????` code as a file sqruff could not check.
