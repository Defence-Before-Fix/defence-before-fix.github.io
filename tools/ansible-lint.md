# ansible-lint

{% include tool-grades.html %}

ansible-lint is the linter for Ansible playbooks, roles and collections: around fifty bundled rules over the YAML and the tasks it describes, profiles from `min` to `production`, and an autofix mode. In a project that ships Ansible it is the usual lint step, run before `ansible-playbook --syntax-check` and in pre-commit or CI, and it is also the natural host for a bespoke defence, because project rules are plain Python classes loaded from a directory.

## How it is conformant

A project rule is a Python class subclassing `AnsibleLintRule` with an `id`, a description and tags, implementing `match` for a line or `matchtask` for a task, and loaded with `-r <dir> -R` so that it runs beside the bundled rules ([custom rules](https://docs.ansible.com/projects/lint/custom-rules/)). A rule `proj-no-debug` written this way fired on a debug task with the same standing as a bundled rule ([4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)). `ansible-lint -r rules -R -t proj-no-debug playbooks/p.yml` reported that rule alone against that one file, and `-t` works the same for a bundled id; the package also ships `ansiblelint.testing.RunFromText`, which its own rule tests use to run a collection against supplied text ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)). The id is chosen once by the rule author and was printed unaltered in the default, `brief`, `full`, `md` and `pep8` output, as `check_name` in `-f json` and as `ruleId` in `-f sarif`, for project and bundled rules alike, and a sub-rule id such as `yaml[truthy]` was printed unaltered in all of those but `pep8` ([4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), partial; see below). It runs locally on a single file with `--offline` ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file), [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)), and every finding is printed in the command's own output with a summary by rule; `--sarif-file` writes SARIF alongside the normal listing ([5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran)).

A bundled id resolves through a URL keyed on it: every finding carries `https://docs.ansible.com/projects/lint/rules/<id>/` (as `url` in JSON, `helpUri` in SARIF and a terminal hyperlink), and `-L` lists every rule with the same link; `rules/yaml/` lists each `yaml[...]` member by name ([6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), for bundled rules). For a project rule the id itself is printed unaltered, which is what clause [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) asks of the detector. Both inline routes are seen by a project rule: a `match` rule `proj-no-inline-skip` fired on a line carrying `# noqa: no-changed-when` and on a `skip_ansible_lint` tag ([muting warnings](https://docs.ansible.com/projects/lint/usage/)). The generated `.ansible-lint-ignore` is loaded automatically, but pointing `-i` at an empty file switched it off (exit 2 instead of 0), and an ignored finding is still printed with `# ignored` unless its line ends in `skip` ([ignoring rules for entire files](https://docs.ansible.com/projects/lint/configuring/)), so that route meets [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable).

## How it is not conformant

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is partial: in `-f pep8` a sub-rule id is printed as `yaml[truthy][/]: Truthy value should be one of [false, true]`, with a stray markup tag appended to the identifier, with or without `--nocolor`, so a consumer of that format reads an identifier that resolves nowhere. Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is partial for `# noqa`: a line ending `# noqa: no-changed-when proj-no-inline-skip` silenced the project rule written to report it, and tagging that rule `unskippable`, which ansible-lint documents as "a fatal error that cannot be ignored or disabled" ([source](https://github.com/ansible/ansible-lint/blob/v26.9.0/src/ansiblelint/rules/__init__.py)), kept it out of `skip_list` but did not stop the `# noqa`, ran; no option switches `# noqa` off. Clause [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fails. Of the 53 bundled ids `-L` lists, 49 have a page installed with the package, as `ansiblelint/rules/<id with underscores>.md`, but `internal-error`, `load-failure`, `parser-error` and `warning` have none; the website has pages for all four. Clause [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) fails: the installed pages are there and `BaseRule.help` reads them ([source](https://github.com/ansible/ansible-lint/blob/v26.9.0/src/ansiblelint/_internal/rules.py)), but no documented command shows them for an id, and their file names turn the id's hyphens into underscores and drop a sub-rule's brackets (`no_changed_when.md`, `yaml.md`), so they are not an index keyed on the id exactly as printed, and the only lookup a practitioner is given is the online URL. That URL is also printed for every project rule: `AnsibleLintRule.url` returns the ansible-lint rules page for whatever id the rule carries and ignores the `link` attribute ([source](https://github.com/ansible/ansible-lint/blob/v26.9.0/src/ansiblelint/rules/__init__.py)), so `proj-no-debug` was printed with `https://docs.ansible.com/projects/lint/rules/proj-no-debug/`, which answered 404, until the rule overrode `url` itself. Clause [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) is still met, since the identifier is printed unaltered, but the dangling link is the kind of reference clause [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) warns against. There is no rule over the rules ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)): a project rule with no `id` in the rules directory produced no finding and no warning, and the id format and uniqueness checks live in ansible-lint's own test suite, which also accepts a description in place of a page ([tests](https://github.com/ansible/ansible-lint/blob/v26.9.0/test/test_rules_collection.py), [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) partial). No route asks for a reason: a comment after `# noqa` is "best practice", and `--generate-ignore` writes one line per file and rule with none ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)).

Readiness is 🟢: a bespoke rule, a single-rule run and a printed identifier all hold. The detector grade is 🟡 because of [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) and [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable). ansible-lint declares no version of this document.

## Notes for a practitioner

Write the class as an `AnsibleLintRule` with a project prefix on its `id`, keep it in a rules directory passed with `-r <dir> -R` in the project's configured command, and prove it red with `-t <id>` against a fixture playbook. Override `url` in the rule class to point at the project's own page for it, or every format will print a link to an ansible-lint page that does not exist. Add a line-matching project rule that fails on `# noqa` and `skip_ansible_lint`, back it with a text search outside ansible-lint, since a `# noqa` naming that rule silences it, and either keep no `.ansible-lint-ignore` or pass `-i` to an empty file, so that every suppression goes through review rather than through the linter.
