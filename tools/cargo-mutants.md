# cargo-mutants

{% include tool-grades.html %}

cargo-mutants is a mutation tester for Rust. It edits a copy of the source tree, one change at a time, such as replacing a function's body with a value of its return type or `>` with `<`, builds and tests each mutant, and reports the mutants the test suite fails to catch ([mutation patterns at v27.1.0](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/mutants.md)). It is not a detector in the method's sense: it judges whether the tests notice a change, not whether a pattern is present in the code, and the method rules out a test as the net. In a pipeline it is the check on the checks, often run only over a diff with `--in-diff`, and it is graded here on whether it could host a defence at all.

## How it is conformant

The reporting clauses are met. `cargo mutants` runs locally against the project's own build and tests, `-f` takes a glob of files to examine, so one file's mutants can be tested alone, and `-D`/`--in-diff` limits the run to code a diff touched (`cargo mutants --help`, ran), which meets [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file) and [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally). The command's own output carries each missed mutant and a summary: a run of 27.1.0 over one file printed six `MISSED` lines and `10 mutants tested in 20s: 6 missed, 4 caught`, and exited 2, the documented code for a missed mutant ([exit codes](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/exit-codes.md)). Fuller detail goes to `mutants.out`, with a JSON description of every mutant and outcome, a diff and a log per mutant and a text file per outcome ([the `mutants.out` directory](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/mutants-out.md)); under reading 8 the default output already prints the findings, so [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) is met. Of its ways of skipping code, `exclude_globs` in `.cargo/mutants.toml` selects the files a run covers, which is configuration and not a route (reading 29); `exclude_re`, the configuration form of `-E`, whose patterns are "matched against the names shown by `--list`", names mutants to leave out and is a route, and `--no-config`, "Don't read .cargo/mutants.toml" (`--help`, ran), switches it off, so it is disableable under reading 17.

## How it is not conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) fails. The mutations are a fixed set in six genres, `FnValue`, `BinaryOperator`, `UnaryOperator`, `MatchArm`, `MatchArmGuard` and `StructField` ([`mutant.rs` at v27.1.0](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/src/mutant.rs)); the options that touch them, `error_values`, `skip_calls` and the name and file filters, choose among or tune the built-in mutations ([error values](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/error-values.md), [skip calls](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/skip_calls.md)), and no documented interface adds one. Graded on the bundled genres, [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) fails: a finding is a mutant the tests missed, so every finding comes from running the project's test suite, which the harness definition excludes; `--list` shows the mutants a file would produce without running tests (ran), but that is the input to a finding, not the finding, and no option selects one genre, only a regular expression over mutant names (`-F`). Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails. The console names a mutant by a string built from its file, line, column and change, `src/lib.rs:3:7: replace + with * in add` (ran), which is derived from the file path and position the clause forbids, and the documentation warns of "Changes to the presentation of mutant names in the console and in JSON" between versions ([stability](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/stability.md)). The nearest thing to a rule identifier, the genre, appears only in the JSON of `--list --json` and `mutants.out` (`"genre": "FnValue"`, ran) and is the name of a variant of the `Genre` enum, so it is derived under reading 5 and absent from the default output.

Section [6](../DETECTOR-SPEC.md#6-resolving-an-identifier) fails. No command looks up a genre or a mutant name, and the documentation is a book in the repository and on the website, not shipped with the installed binary. Its [mutation patterns](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/mutants.md) page names only `FnValue` as printed; the other genres are under headings such as "Binary operators", a different spelling under reading 11, so [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) are No.

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fails on the inline route. `#[mutants::skip]`, on a function, `impl`, `trait`, module, file or expression, and in a `cfg_attr` whatever its condition ([skipping with an attribute](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/attrs.md)), is applied by an unconditional check in the source visitor ([`visit.rs` at v27.1.0](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/src/visit.rs)), no option turns it off, and nothing lists or counts what it skipped: a skipped function simply has no mutants in `--list` (ran). The documentation says the results of the filters "can be previewed using the `--list` option" ([skipping untestable code](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/skip.md)), but that lists what is left, not what was skipped, so under reading 18 it does not make the route detectable. cargo-mutants runs no project rule that could see it, so the route is neither disableable nor detectable. The same visitor skips, by the same unconditional test, code under `#[cfg(test)]` and any item under an attribute whose path ends in `test`, such as `#[tokio::test]` ([mutation patterns](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/book/src/mutants.md); `attrs_excluded` in [`visit.rs`](https://github.com/sourcefrog/cargo-mutants/blob/v27.1.0/src/visit.rs)); those markers are there to mark tests, but under reading 29 a marker in the checked code that makes the tool skip a region is a route, and these too have no switch (`--help`, ran) and no report. Clause [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) fails under reading 30, since no route asks for a reason: the attribute takes none, and the documentation says only "You may want to also add a comment explaining why the item is skipped"; an `exclude_re` entry is a bare regular expression, and the test markers carry none. Clause [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is No under reading 28: no mechanism keyed on a printed mutant name or genre reaches a page, as [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) records, so no bundled identifier lands on one, whatever the release process holds; that every genre is described under some heading of the mutation patterns page does not make it land. Nothing enforces [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), and with no project rules at all [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is No, not Not applicable (reading 7).

Recorded under reading 9: a source file that does not parse stopped the run with `Error: failed to parse src/other.rs` and exit 1, the same code as a usage error, so the failure is visible (ran).

The detector grade is 🔴 on [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it), [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) and [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), all structural under reading 1, with section [6](../DETECTOR-SPEC.md#6-resolving-an-identifier), [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) and [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) failing as well. Readiness is 🔴: no bespoke rules and no stable identifier on findings.

## Notes for a practitioner

Use cargo-mutants to check that the reproduction test under clause 2 of the method actually constrains the fix: run it over the files the fix touched, with `-f` or `--in-diff`, and a missed mutant in the fixed code is a test that would not go red. Build the defence itself in a detector. If you skip code with `#[mutants::skip]`, write the reason in a comment beside it and forbid the bare attribute with a rule in a detector that can see attributes, such as a Dylint lint, because cargo-mutants will neither require the reason nor show you what it skipped. Read `mutants.out/outcomes.json` when a script needs the genre of each mutant, since the console does not print it.
