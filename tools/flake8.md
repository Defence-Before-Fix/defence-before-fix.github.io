# Flake8

{% include tool-grades.html %}

Flake8 is a thin driver that runs pyflakes, pycodestyle and mccabe and, more importantly, any plugin registered through a Python entry point. It is the origin of the letter-plus-digits code convention that Ruff later adopted, and its plugin ecosystem is why it survives Ruff: a project that needs a rule nobody has written can write it as a small package and Flake8 will run it beside everything else.

## How it is conformant

Bespoke rules are the design. [Registering plugins](https://flake8.pycqa.org/en/latest/plugin-development/registering-plugins.html) shows the `flake8.extension` entry point whose name "acts as a prefix to the error codes produced by your plugin", so the rule author chooses a code such as `X101` once and it is neither the class name nor the file path, and Flake8 prints it with every finding in its default and machine-readable formats ([4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it), [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding)). Flake8 runs locally on one file and every plugin runs locally ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file), [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)), and by default every finding is printed with its code in the command's output. Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) holds: `# noqa` is the inline route and the `--disable-noqa` option makes Flake8 ignore every such comment ([violations](https://flake8.pycqa.org/en/latest/user/violations.html)), so a project that forbids the route can switch it off in the enforced invocation. It covers the file-level form as well: at 7.4.1 a file headed `# flake8: noqa` passed with exit 0, and with `--disable-noqa` both of its unused imports were reported as `F401` and the run exited 1.

## How it is not conformant

Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is partial. `flake8 --select X101 fixture.py` prints the findings of one code ([selecting violations](https://flake8.pycqa.org/en/latest/user/violations.html)), bundled or bespoke, but it runs every plugin and filters what is printed: the plugin finder sorts the loaded plugins into tree, logical-line and physical-line checkers without consulting the selection ([`plugins/finder.py`](https://github.com/PyCQA/flake8/blob/7.4.1/src/flake8/plugins/finder.py#L310)), and at 7.4.1 a second local plugin, registered as `Y2`, that wrote a file whenever it ran wrote it under `--select X1`, whilst only `X101` was printed; when that plugin raised an exception instead, the same `--select X1` run stopped with its `RuntimeError` (ran). That is a print filter, not a run of a single rule (reading 21), and Flake8 documents no other harness, so the row is Partial and readiness 🟡 (reading 2). Section [6](../DETECTOR-SPEC.md#6-resolving-an-identifier) fails for the bundled codes, which decide the row. Flake8 ships no command that resolves a printed code, installs no index of them, and prints no address with its findings: the default and `pylint` formats print the code and the message alone (ran at 7.4.1). Two web pages list most of the bundled codes as printed, each with a one-line example message: Flake8's [error codes](https://flake8.pycqa.org/en/7.4.1/user/error-codes.html) page, for every `F` code its pyflakes mapping can print with `C901` and `E999`, and pycodestyle's [error codes](https://pycodestyle.pycqa.org/en/2.15.0/intro.html#error-codes) table, for its `E` and `W` codes. Neither is a mechanism Flake8 provides under reading 10: it does not print them, and its documentation does not state an address with the code placed in it as the way to look one up, saying only that "Most plugins will list their error codes in their documentation or README" ([error codes at 7.4.1](https://github.com/PyCQA/flake8/blob/7.4.1/docs/source/user/error-codes.rst)). So [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) fails, and [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fail with it (reading 14). The lists are incomplete as well: `E252`, which pycodestyle 2.15.0 prints for a missing space around a parameter's default (`E252 missing whitespace around parameter equals`, ran with Flake8 7.4.1), is in neither, at that version's documentation or the latest (compared on the checked date), and the practitioner must know which plugin owns a prefix to know which list to read. A bespoke plugin can ship its own descriptions, but that is the project's doing and not Flake8's. No reason is asked for on a `# noqa` comment, line or file-level, and no option makes one required, so [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) is No on every route (reading 30); Flake8 honours no generated-code header or other skip marker besides `# flake8: noqa` (its 7.4.1 source matches only the `noqa` forms; reading 29). Clause [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) is partial: the documented [`--output-file`](https://flake8.pycqa.org/en/latest/user/options.html#cmdoption-flake8-output-file) option leaves the command's own output empty, with no count and no file name (ran at 7.4.1: nothing on standard output or standard error, exit 1), unless [`--tee`](https://flake8.pycqa.org/en/latest/user/options.html#cmdoption-flake8-tee) is added, when the findings are printed as well. Clause [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) asks for "a Rule over the Rules, failing any Rule that reports without a stable Identifier", and Flake8 has none. Its plugin finder refuses to start when an entry point name does not match `^[A-Z]{1,3}[0-9]{0,3}$` ([`plugins/finder.py`](https://github.com/PyCQA/flake8/blob/7.4.1/src/flake8/plugins/finder.py#L338)), a refusal at load that enforces the prefix's form, so [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is partial; it is not a rule, it does not test stability, and it does not bind the codes a plugin reports: at 7.4.1 a plugin registered as `X1` that reported `Q777` printed `Q777` once that code was selected. Clause [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is not met: with no mechanism of Flake8's own, no bundled code lands on a page in the sense of reading 28, since the code lists are pages no mechanism keyed on the code reaches, so 7.4.1 shipped every bundled code landing on no page, and `E252`, which it prints through pycodestyle 2.15.0, is not even on those lists. The detector grade is 🟡: no structural clause fails, and [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) and [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) partial and [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) to [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) and [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) failing are named above (reading 1). Readiness is 🟡: bespoke rules and a printed identifier, with one code run alone only through a print filter.

## Notes for a practitioner

Write the class as a small plugin with its own prefix, register it through `flake8.extension`, and prove it with `flake8 --select <code> fixture.py` before sweeping, knowing that every other installed plugin still runs in that invocation, so a crash in one of them fails the proof. Run with `--disable-noqa` in the enforced invocation so inline suppressions have no effect, add `--tee` wherever `--output-file` is used, and keep the plugin's README in the repository next to its source so the code resolves by convention even though Flake8 offers no resolver.
