# Konsist

{% include tool-grades.html %}

Konsist is a Kotlin library for checking a codebase's structure in unit tests: a test takes a scope of source files, such as `Konsist.scopeFromProduction()`, filters its declarations, and asserts a condition over them with `assertTrue` or `assertFalse`, or asserts layer dependencies with `assertArchitecture`. It reads Kotlin source through the compiler's syntax tree and ships no rules of its own. In a project's checks it runs in the test suite, under JUnit or Kotest, so the test runner's command is the one the practitioner invokes.

## How it is conformant

Every Konsist rule is the project's own ([4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)). Ran at 0.18.1 with JUnit 5 through Gradle 9.8.1 and Kotlin 2.4.21 on JDK 21: a test asserting that no class name ends in `Manager` failed with `Assert 'proj.no-manager-suffix' was violated (2 times). Invalid declarations:` and one line per class with its file, line and column. One rule runs alone against supplied code ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)): `Konsist.scopeFromFile(path)` builds a scope from one file, relative to the project root ([`KoScopeCreator.kt` at the tag](https://github.com/LemonAppDev/konsist/blob/v0.18.1/lib/src/main/kotlin/com/lemonappdev/konsist/api/container/KoScopeCreator.kt)), and `gradle test --tests 't.KoTest.oneFile'` ran that test alone and reported the one class in that file. Konsist reads source, so nothing has to be compiled first.

Every assertion is evaluated on the practitioner's own machine, with no service or licence ([5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)). Konsist ships no bundled rules, so [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) to [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) have nothing to apply to (reading 28).

## How it is not conformant

Clauses [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) and [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file) fail, both structurally (reading 1). Konsist is a library with no command of its own: its repository at the tag holds the `lib` library, samples and build logic and no command-line entry point (the tree listed), and the only documented way to run it is a test the practitioner writes, which builds a scope, filters it and asserts, and which the test runner then executes ([assert](https://docs.konsist.lemonappdev.com/features/assert)). That is a detector reached only through its programming interface, which is not invocable by the practitioner (reading 23). The files a run covers are chosen in the same program: `Konsist.scopeFromFile(path)` builds a scope from one file, relative to the project root ([`KoScopeCreator.kt` at the tag](https://github.com/LemonAppDev/konsist/blob/v0.18.1/lib/src/main/kotlin/com/lemonappdev/konsist/api/container/KoScopeCreator.kt)), but nothing on the command line names a file, so a run over one file exists only as code written for it (readings 22 and 23). Clause [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) fails with them, under reading 23. Konsist prints nothing of its own: a failed assertion throws a `KoAssertionFailedException` whose message holds the report ([`KoDeclarationAndProviderAssertCore.kt` at the tag](https://github.com/LemonAppDev/konsist/blob/v0.18.1/lib/src/main/kotlin/com/lemonappdev/konsist/core/verify/KoDeclarationAndProviderAssertCore.kt)), and it is the test runner, executing the test the practitioner wrote, that prints it: with Gradle's default test logging the console named the failing test and printed the path of the HTML report, with `exceptionFormat = 'full'` it printed the whole message, and the build exited 1, ran. That is the program's output, not the detector's. Clause [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) fails for the same reason: of a project's own rule it asks only that the identifier be printed unaltered (reading 13), and Konsist prints none.

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is No under reading 23, since the detector prints nothing, so no identifier; what the test runner prints from the thrown message is a workaround that moves readiness only (reading 2). Were it Konsist's own output, the clause would still be only partial. The identifier in the message is `testName` where the author passes one, and otherwise the name of the test function, read from the call stack ([`KoDeclarationAndProviderAssertCore.kt` at the tag](https://github.com/LemonAppDev/konsist/blob/v0.18.1/lib/src/main/kotlin/com/lemonappdev/konsist/core/verify/KoDeclarationAndProviderAssertCore.kt)): ran, the same assertion without `testName` printed `Assert 'classesShouldNotEndWithManager' was violated`, which changes when the function is renamed. An author-chosen identifier that a rule carries only when one is passed, with a derived one by default, is graded as reading 5 grades one printed only under a flag. `testName` is described in the documentation as the name that "helps with suppression" ([assert](https://docs.konsist.lemonappdev.com/features/assert)). Konsist offers no machine-readable format of its own; the runner's JUnit XML carries the message under the test function's name. Nothing enforces an identifier: `testName` is optional, and there is no rule over the rules, so [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is No (reading 7).

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is partial. `@Suppress("<name>")` or `@Suppress("konsist.<name>")`, with the test's identifier, on a declaration, any declaration containing it, or the file, removes that declaration from the assertion ([suppressing a Konsist test](https://docs.konsist.lemonappdev.com/writing-tests/suppressing-konsist-test)); ran, a class annotation with the prefix and a file annotation without it both silenced the rule. The check runs on every assertion, with no setting to turn it off, and nothing reports what it removed. A project test can see the annotations, since Konsist reads them: ran, `proj.no-konsist-suppress` reported the two classes whose `@Suppress` named a test with the `konsist.` prefix. But a third class annotated `@Suppress("konsist.proj.no-manager-suffix", "konsist.proj.no-konsist-suppress")` was silenced for both tests in the same run, so the route is detected only in part (reading 19). No other marker in the checked code, such as a generated-code annotation, makes Konsist skip a declaration or file (read, the `lib` module at the tag; reading 29). Clause [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) is No, asked of its one route (reading 30): `@Suppress` takes no reason.

Readiness is 🟡: a bespoke rule and a single-rule run hold, and an author-chosen identifier, once `testName` is passed, reaches the output only in the message the test runner prints, a workaround (readings 2 and 23). The detector grade is 🔴 because [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) and [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file) fail, both structural (reading 1), and [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is No with them; [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) and [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) fail and [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is partial as well. A file that does not parse was read without complaint, and its class was still reported, ran. Konsist takes the project root from a Gradle or Maven wrapper or a Git directory ([`ProjectRootDirProviderFactory.kt`](https://github.com/LemonAppDev/konsist/blob/v0.18.1/lib/src/main/kotlin/com/lemonappdev/konsist/core/filesystem/ProjectRootDirProviderFactory.kt)); in a probe without either, nested in a larger repository, `scopeFromProduction()` covered the whole enclosing repository until the probe had a `.git` of its own, ran. Konsist declares no version of this document.

## Notes for a practitioner

Pass `testName = "proj.<name>"` to every assertion, so the printed identifier does not move when the test function is renamed, and keep the index from those names to their documentation in the repository. Prove the rule with `scopeFromFile` on a fixture file, and run it alone through the test runner's filter. If inline suppression is to be forbidden, write a test over declarations and files that fails on any `@Suppress` argument naming a Konsist test, and remember that the same annotation can name that test too, so review is still needed. Give the project a `.git` or a build wrapper at its root, so that a scope covers the project and nothing above it.
