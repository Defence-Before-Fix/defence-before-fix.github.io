# Nu Html Checker

{% include tool-grades.html %}

The Nu Html Checker, `vnu`, is the HTML conformance checker behind the W3C's online validator, shipped as a Java jar, a runtime image and the `vnu-jar` npm package. It parses a document with the HTML parser, validates it against a RELAX NG schema of the HTML standard and runs Java checkers for the rules a schema cannot express, such as duplicate IDs and the `alt` requirement; `--css` and `--svg` check those languages too. In a pipeline it is the check that markup is valid HTML, run over built pages or rendered templates.

## How it is conformant

Section [5](../DETECTOR-SPEC.md#5-reporting) is met. `java -jar vnu.jar a.html` ran locally with the network removed (`unshare -rn`) and printed every finding with its position and exited 1; it takes one file, a directory or `-` for standard input ([`vnu.1.md`](https://github.com/validator/validator/blob/3d97faa/docs/vnu.1.md); ran), so [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file) and [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally) hold. Findings go to standard error, or standard output with `--stdout`, and nothing is written elsewhere, so [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) holds.

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is met. A document can carry no instruction to the checker: a `<!-- vnu-disable -->` comment above an image without `alt` left the error in place (ran), and the documentation lists no inline route ([message filtering](https://github.com/validator/validator/blob/3d97faa/docs/wiki/Message-filtering.md)). The routes it does offer for the command line, `--filterfile` and `--filterpattern`, drop any message matching a regular expression, and they apply only when the invocation names them, so a project that leaves them out has them off. The servlet's global `resources/message-filters.txt` belongs to a self-hosted service, not to the command. With no inline route, [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) does not apply.

## How it is not conformant

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails, and under reading 5 it is No: no check carries an identifier. The default GNU output prints the file, position, severity and message, `5.1-5.10: error: Duplicate ID “x”.`, and the JSON messages carry `type`, `subType`, `message`, `extract` and positions; the XML and text formats likewise carry the message alone (all four formats ran). A message is the only thing a reader holds, and it changes with the wording. Section [6](../DETECTOR-SPEC.md#6-resolving-an-identifier) fails with it: there is no identifier for a mechanism to resolve, so [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) are No (reading 14), and [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is No. Some messages carry their own guidance, such as the `alt` message's link to the WAI images tutorial in the XML output, which resolves that message, not an identifier.

Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) fails. No option selects one check (`--help`, ran): the options choose the language, the parser, the severity printed and the filters. A `--filterpattern` can hide every message but those matching a text, but that filters output by wording, and with no identity to select a check by, no check can be run on its own.

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) is partial. The `--schema` option, listed in `--help` without a description, takes an `http:`, `https:` or `file:` URL and makes that schema the main one ([`SimpleCommandLineValidator.java`](https://github.com/validator/validator/blob/3d97faa/src/nu/validator/client/SimpleCommandLineValidator.java)). A project schema in RELAX NG compact syntax that included the bundled `http://s.validator.nu/html5-all.rnc` and set `b.elem = notAllowed` loaded offline and reported `Element “b” not allowed as child of element “p”` (ran), so a pattern of the project's own can be expressed. It does not run with the same standing as the bundled checks: replacing the main schema dropped the bundled `alt` check from the same run, and the project's finding, like every other, has no identifier. No rule over the rules exists ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)).

A path that does not exist printed nothing and exited 0, and an unknown option such as `--bogus` was ignored with exit 0 (ran); the checker never fails to parse HTML, since the HTML parser recovers from anything, and a binary file was reported as a list of errors with exit 1.

The detector grade is 🔴 because [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) and [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) are No, both structural under reading 1; [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) and [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) to [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fail as well. Readiness is 🔴: no finding carries a stable identifier. The checker declares no version of this document.

## Notes for a practitioner

Run the checker for what it is, the authority on whether markup is valid HTML, and write the project's own markup classes in a host that carries identifiers, such as html-validate or ESLint with `@html-eslint`. A defence routed through it would have to be keyed on message text, which is not stable. Keep `--filterfile` and `--filterpattern` out of the enforced invocation or review the filter file as a record, since nothing reports what a filter dropped, and check that the files given exist, since a missing path and a misspelt option both pass with exit 0. The npm package `vnu-jar` pins a release of the jar; the GitHub release named `latest` moves.
