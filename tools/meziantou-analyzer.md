# Meziantou.Analyzer

{% include tool-grades.html %}

Meziantou.Analyzer is a set of C# rules on correctness, performance, security and design, published as a NuGet analyser package and run inside an ordinary `dotnet build` on the [Roslyn host](roslyn-analyzers.md). Its rules carry identifiers such as `MA0074`. Besides its fixed rules it has `MA0240`, "Do not use banned syntax", which reports whatever a project lists in a `BannedSyntaxes.txt` file. A project can therefore write a rule of its own in this package without writing an analyser. This page grades what the package adds to the host, as the [SonarAnalyzer.CSharp](sonaranalyzer-csharp.md) page does.

## How it is conformant

A project writes a rule as a line of `BannedSyntaxes.txt` ([4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)). The line is an XPath 1.0 query over the file's syntax tree, with attributes in a `semantic` namespace for the type or symbol a node binds to, followed by a severity and a message ([`MA0240.md`](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/docs/Rules/MA0240.md)). The package adds the nearest such file to the build by itself. Ran: the line `//SimpleMemberAccessExpression[@semantic:SymbolDocumentationId='P:System.DateTime.Now'];error;proj.no-datetime-now: read the clock through IClock` made `dotnet build` print `error MA0240: The syntax 'SimpleMemberAccessExpression' is banned: proj.no-datetime-now: read the clock through IClock` on `DateTime.Now` and not on `DateTime.UtcNow`, and fail the build. The query sees resolved symbols, so it is a pattern the package's authors did not write, reported with the standing of their own rules.

One rule runs alone against supplied code through the Roslyn test package ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)). Each rule's page links the analyser's source file, as [`MA0074.md`](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/docs/Rules/MA0074.md) links `UseStringComparisonAnalyzer.cs`. Ran: Microsoft.CodeAnalysis.CSharp.Analyzer.Testing version 1.1.4 ran `UseStringComparisonAnalyzer` alone against a source string marked `{|MA0074:...|}`. It also ran `DoNotUseBannedSyntaxAnalyzer` with the query above as its only additional file. Each passed on the right span and failed on a wrong one.

The package runs where the build runs, with no service ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure)). Ran with the network removed: `dotnet build ma.cs` on a one-file app with `#:package Meziantou.Analyzer@3.0.296` printed `warning MA0074: Use an overload of 'StartsWith' that has a StringComparison parameter (https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0074.md)`. It ran on one file with no project ([5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file)), and the finding was in the command's own output ([5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran)). Nothing is held back for a service or licence tier ([5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)).

Every identifier a finding prints is followed by an address keyed on it exactly as printed, `docs/Rules/<id>.md` in the project's repository ([6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation)). Ran: all 238 descriptors in the package have that page, at the tag and on `main`. Clause [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is met. The `check_documentation` job in [`ci.yml`](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/.github/workflows/ci.yml) runs the [documentation generator](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/src/DocumentationGenerator/Program.cs), which exits non-zero when it has to write a file. That happens when a rule has no page, and also when an address does not contain its identifier, which throws. The `deploy` job needs that job to pass.

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) holds for each route that hides one of the package's findings. Ran: in the host's SARIF log a pragma-hidden `MA0074` carried `"suppressionType": "Pragma Directive"` and an attribute-hidden one `SuppressMessageAttribute`. A `// <auto-generated/>` header hid every `MA` finding, and `generated_code = false` in `.editorconfig` brought them back. The package also ships four suppressors, `MAS0001` to `MAS0004`, listed in its README, which hide findings of the host's own rules in known cases. Ran: `MAS0003` hid an `IDE0058` finding on `StringBuilder.Append`, and the SARIF log recorded it as `DiagnosticSuppressor { Suppression Id: MAS0003, ... }`. Setting `dotnet_diagnostic.MAS0003.severity = none` did not stop it.

## How it is not conformant

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is partial. The package's own rules carry identifiers its maintainer assigned once, constants in [`RuleIdentifiers.cs`](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/src/Meziantou.Analyzer/RuleIdentifiers.cs), printed unaltered on the console and as `ruleId` in SARIF (ran). A project's query cannot carry one: every line of `BannedSyntaxes.txt` reports as `MA0240`, so two defences in the same file print the same identifier. The only place for the project's own identifier is the message, after the fixed prefix `The syntax '<kind>' is banned: `, as `proj.no-datetime-now` was above. Under reading 2 that is a workaround for readiness and does not meet the clause. A `#pragma warning disable MA0240` silences every query at once. There is no rule over the identifiers either ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)). `MA0241` reports a query or severity it cannot parse, but nothing asks a query for an identifier.

The documentation does not ship ([6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together)). Ran: the package holds the assemblies, preset `.editorconfig` files and a `README.md` whose table names every one of the 238 identifiers. Each entry gives only a category, a title such as "Avoid implicit culture-sensitive methods" and the defaults, and it links to the GitHub page. Under reading 12, and as the [Roslyn host](roslyn-analyzers.md) page counts a SARIF rules table, a title alone is not the rule's documentation. Only 4 of the 238 descriptors carry a description for the host's SARIF rules table (ran). The printed address also points at `main`, not at the release installed. No reason is asked of a suppression ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)): the package has no rule like StyleCop.Analyzers' `SA1404`.

The detector grade is 🟡: no structural clause fails, and [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) are the MUSTs that do not hold in full. Readiness is 🟡: a project can write a rule and run it alone, but its identifier exists only inside the message.

## Notes for a practitioner

A defence that needs nothing beyond syntax and bound symbols can be a line of `BannedSyntaxes.txt` rather than an analyser. Start its message with the project's identifier, give it `error` severity, and prove it with the Roslyn test package, passing the query as the only additional file. Be aware that every such line shares `MA0240`: an inline suppression of one silences all of them, so a project that allows suppressions for other rules should not allow them for `MA0240`. Read the SARIF log, not only the console, to see what the `MAS` suppressors hid. Set `generated_code = false` for the project's own sources, so that a `<auto-generated/>` header does not hide a file from the package.
