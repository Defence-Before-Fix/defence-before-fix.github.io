# Meziantou.Analyzer

{% include tool-grades.html %}

Meziantou.Analyzer is a set of C# rules on correctness, performance, security and design, published as a NuGet analyser package and run inside an ordinary `dotnet build` on the [Roslyn host](roslyn-analyzers.md). Its rules carry identifiers such as `MA0074`. Besides its fixed rules it has `MA0240`, "Do not use banned syntax", which reports whatever a project lists in a `BannedSyntaxes.txt` file. A project can therefore write a rule of its own in this package without writing an analyser. This page grades what the package adds to the host, as the [SonarAnalyzer.CSharp](sonaranalyzer-csharp.md) page does.

## How it is conformant

A project writes a rule as a line of `BannedSyntaxes.txt` ([4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)). The line is an XPath 1.0 query over the file's syntax tree, with attributes in a `semantic` namespace for the type or symbol a node binds to, followed by a severity and a message ([`MA0240.md`](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/docs/Rules/MA0240.md)). The package adds the nearest such file to the build by itself. Ran: the line `//SimpleMemberAccessExpression[@semantic:SymbolDocumentationId='P:System.DateTime.Now'];error;proj.no-datetime-now: read the clock through IClock` made `dotnet build` print `error MA0240: The syntax 'SimpleMemberAccessExpression' is banned: proj.no-datetime-now: read the clock through IClock` on `DateTime.Now` and not on `DateTime.UtcNow`, and fail the build. The query sees resolved symbols, so it is a pattern the package's authors did not write, reported with the standing of their own rules.

One of the package's own rules runs alone against supplied code through the Roslyn test package, and a project's query only from a file written for the run ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code), below). Each rule's page links the analyser's source file, as [`MA0074.md`](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/docs/Rules/MA0074.md) links `UseStringComparisonAnalyzer.cs`. Ran: Microsoft.CodeAnalysis.CSharp.Analyzer.Testing version 1.1.4 ran `UseStringComparisonAnalyzer` alone against a source string marked `{|MA0074:...|}`. It also ran `DoNotUseBannedSyntaxAnalyzer` with the query above as its only additional file. Each passed on the right span and failed on a wrong one. For the bundled rules that is a test harness, which reading 4 counts as Yes.

The package runs where the build runs, with no service ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure)). Ran with the network removed: `dotnet build ma.cs` on a one-file app with `#:package Meziantou.Analyzer@3.0.296` printed `warning MA0074: Use an overload of 'StartsWith' that has a StringComparison parameter (https://github.com/meziantou/Meziantou.Analyzer/blob/main/docs/Rules/MA0074.md)`. It ran on one file with no project ([5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file)), and the finding was in the command's own output ([5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran)). Nothing is held back for a service or licence tier ([5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)).

Every identifier one of the package's findings prints is followed by an address keyed on it exactly as printed, `docs/Rules/<id>.md` in the project's repository, which meets [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) for those identifiers, though not for the compiler's (below). Ran: all 238 descriptors in the package have that page, at the tag and on `main`. Clause [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is met: every `MA` identifier lands on a page through the printed address, and the release process holds a check that covers every one (reading 28). The `check_documentation` job in [`ci.yml`](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/.github/workflows/ci.yml) runs the [documentation generator](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/src/DocumentationGenerator/Program.cs), which exits non-zero when it has to write a file. That happens when a rule has no page, and also when an address does not contain its identifier, which throws. The `deploy` job needs that job to pass.

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) holds for each route that hides one of the package's findings. Ran: in the host's SARIF log a pragma-hidden `MA0074` carried `"suppressionType": "Pragma Directive"` and an attribute-hidden one `SuppressMessageAttribute`. A `// <auto-generated/>` header hid every `MA` finding, and `generated_code = false` in `.editorconfig` brought them back. The `[GeneratedCode]` attribute is a route too (reading 29), and that setting does not close it. Ran: in a project, a class marked `[GeneratedCode("gen", "1")]` printed none of the `MA0016`, `MA0020`, `MA0031`, `MA0038` and `MA0074` findings its unmarked twin printed, and a project query `//Attribute` in `BannedSyntaxes.txt` reported `MA0240` on a `[Serializable]` attribute but not on the `[GeneratedCode]` one, so the attribute hides itself from a rule written to find it; `generated_code = false` changed neither, and the SARIF log recorded no suppression. The package documents its own switch ([analyzing generated code](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/docs/generated-code.md), and the installed README): the environment variable `MEZIANTOU_ANALYZER_GENERATED_CODE=true` makes the rules analyse generated code and `MA.report_generated_code = true` in `.editorconfig` makes them report there. Ran with both, after `dotnet build-server shutdown`: every one of those findings came back in the marked class, and `MA0240` reported the `[GeneratedCode]` attribute. The route can be switched off, so it is disableable (reading 17). The package also ships four suppressors, `MAS0001` to `MAS0004`, listed in its README, which hide findings of the host's own rules in known cases. Ran: `MAS0003` hid an `IDE0058` finding on `StringBuilder.Append`, and the SARIF log recorded it as `DiagnosticSuppressor { Suppression Id: MAS0003, ... }`. Setting `dotnet_diagnostic.MAS0003.severity = none` did not stop it.

## How it is not conformant

A project's query runs alone only through configuration ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)). `DoNotUseBannedSyntaxAnalyzer` runs every line of the `BannedSyntaxes.txt` it is given, and nothing selects one line: the test above ran one query alone only because its additional file, written for the test, held no other. Selecting one rule through a file the practitioner writes for the run is configuration, so [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is Partial for the rules a defence is written as (reading 21).

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is not met. The package's own rules carry identifiers its maintainer assigned once, constants in [`RuleIdentifiers.cs`](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/src/Meziantou.Analyzer/RuleIdentifiers.cs), printed unaltered on the console and as `ruleId` in SARIF (ran). A project's query cannot carry one: every line of `BannedSyntaxes.txt` reports as `MA0240`, so two defences in the same file print the same identifier (ran: a `DateTime.Now` query and a `GotoStatement` query both printed `MA0240`). The only place for the project's own identifier is the message, after the fixed prefix `The syntax '<kind>' is banned: `, as `proj.no-datetime-now` was above. The project can write rules, but none of them can carry an identifier of its own, so [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is No, and structural, however the bundled rules are identified (reading 20). The identifier in the message is a workaround for readiness (reading 2) and does not meet the clause. A `#pragma warning disable MA0240` silences every query at once. There is no rule over the identifiers either, so [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is No (reading 7). `MA0241` reports a query or severity it cannot parse, but nothing asks a query for an identifier.

The command that runs the package is `dotnet build`, and it prints the compiler's identifiers beside the package's, with no address: ran, a one-file app with the package printed `warning CS0168: The variable 'unused' is declared but never used` with nothing after it, beside `MA0074` and its address. Those identifiers count (reading 27), and nothing the package or the host provides resolves them, as the [Roslyn host](roslyn-analyzers.md) page finds, so [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) is Partial.

The documentation does not ship ([6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together)). Ran: the package holds the assemblies, preset `.editorconfig` files and a `README.md` whose table names every one of the 238 identifiers. Each entry gives only a category, a title such as "Avoid implicit culture-sensitive methods" and the defaults, and it links to the GitHub page. The README heads that column "Description", but the [documentation generator](https://github.com/meziantou/Meziantou.Analyzer/blob/3.0.296/src/DocumentationGenerator/Program.cs) fills it from each descriptor's `Title` (read), the same text that heads the rule's own page, so it is the name the package gives the rule, and a title or name is not documentation however much it says (reading 12, whose own example is this one). Only 4 of the 238 descriptors carry a description for the host's SARIF rules table (ran), and that table is the report of one build, not a mechanism (reading 26). The printed address also points at `main`, not at the release installed. No route asks a reason ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason), reading 30): the package has no rule like StyleCop.Analyzers' `SA1404`, and a pragma, an optional `Justification`, the header and the `[GeneratedCode]` attribute take none.

The detector grade is 🔴: [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), a structural MUST, is No (readings 1 and 20). Clauses [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) and [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) are partial, and [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fail, with the SHOULDs [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) and [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason). Readiness is 🟡: a project can write a rule and run it alone from a file of its own, and its identifier, written at the start of the message, prints whole (reading 2).

## Notes for a practitioner

A defence that needs nothing beyond syntax and bound symbols can be a line of `BannedSyntaxes.txt` rather than an analyser. Start its message with the project's identifier, give it `error` severity, and prove it with the Roslyn test package, passing the query as the only additional file. Be aware that every such line shares `MA0240`: an inline suppression of one silences all of them, so a project that allows suppressions for other rules should not allow them for `MA0240`. Read the SARIF log, not only the console, to see what the `MAS` suppressors hid. Set `generated_code = false` for the project's own sources, so that a `<auto-generated/>` header does not hide a file from the package, and, where a `[GeneratedCode]` attribute could appear in hand-written code, set `MEZIANTOU_ANALYZER_GENERATED_CODE=true` in the build's environment with `MA.report_generated_code = true`, since only that brings back what the attribute hides; the compiler server keeps the environment it started with, so shut it down after changing the variable.
