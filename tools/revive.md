# revive

{% include tool-grades.html %}

revive is the configurable successor to golint: about a hundred rules, such as `var-naming` and `exported`, enabled and tuned from a TOML file, with comment directives to disable them in place ([README at v1.17.1](https://github.com/revive-lint/revive/blob/v1.17.1/README.md)). In a pipeline it runs on its own or as the `revive` linter inside golangci-lint. It is built to be extended: a project can write rules in Go and build a revive binary that runs them beside the bundled ones.

## How it is conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) is met. The README's "Using revive as a library" section has a project implement the `lint.Rule` interface, a `Name()` and an `Apply()` over the parsed file, and pass it to `cli.RunRevive(revivelib.NewExtraRule(&myRule{}, lint.RuleConfig{}))` in a `main` package of its own ([README](https://github.com/revive-lint/revive/blob/v1.17.1/README.md)). Built against v1.17.1, such a binary ran a rule named `proj-no-os-remove` and a second, `proj-no-revive-directive`, that reads the file's comments, beside the bundled rules, with the same configuration, directives and formatters (ran). The name is a string the rule's author returns, chosen once and not derived from the type's name, and the bundled rules' names are assigned the same way by the maintainers.

The binary runs locally on a single file, `revive a.go`, or on package patterns, and prints findings in the command's own output; there is no option that writes them elsewhere, which meets [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) to [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally) (ran). Clause [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) is met by configuration: with `[directive.specify-disable-reason]` a directive with no trailing text was reported as `reason of lint disabling not found` and no longer suppressed the finding under it (ran), and the README documents `[directive.specify-disable-rule]` as forbidding a directive that names no rule ([README](https://github.com/revive-lint/revive/blob/v1.17.1/README.md)). Both are off by default, and neither reaches the generated-code header described under [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable), which takes no reason, so the row is Partial.

## How it is not conformant

Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is partial under readings 4 and 21, which make a configuration the practitioner writes for the run Partial. There is no flag that selects a rule, and the rule tests in the repository's `test` package are not importable by a project ([`test/`](https://github.com/revive-lint/revive/tree/v1.17.1/test)), so one rule runs alone only through a configuration that names it; and a rule added with `NewExtraRule` is enabled whether the configuration names it or not ([`core.go`](https://github.com/revive-lint/revive/blob/v1.17.1/revivelib/core.go#L52)), so that configuration must also disable every other project rule: a configuration naming only `proj-no-os-remove` still printed a `proj-no-revive-directive` finding (ran).

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is partial. The `default` formatter, the one used when none is named, prints no rule name: `a.go:6:6: use the safe deleter` (ran). The `unix` formatter prints `[proj-no-os-remove]`, and `json`, `ndjson` and `sarif` carry the name unaltered as `RuleName` and `ruleId`. The `plain`, `friendly` and `stylish` formatters print it only inside `https://revive.run/r#proj-no-os-remove`, and `checkstyle` as `source="revive/proj-no-os-remove"`, a constant prefix joined to the name, which alters it under reading 6 (ran). Clause [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is not met: `revivelib.New` registers an extra rule under whatever `Name()` returns, with no check of its form ([`core.go`](https://github.com/revive-lint/revive/blob/v1.17.1/revivelib/core.go)), and a `Name()` that returns a string can return an empty one, so the interface does not make a nameless rule inexpressible either (reading 7).

Section [6](../DETECTOR-SPEC.md#6-resolving-an-identifier) rests on that printed URL, which reading 10 accepts as the mechanism, and its anchor is the identifier exactly. On 2026-10-10 the page at `https://revive.run/r/` had an anchor for each of the 105 rule names in the source at v1.17.1, but revive also prints `specify-disable-reason` and `specify-disable-rule` as rule names for the directive checks, and neither has an anchor there (ran), so [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) is partial. The page is on the web only: the release archive holds the binary, the README and the licence, and nothing that resolves a name from the installed copy, so [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fail. The README's table of rules, which ships in the archive, names each rule beside a one-line description, but it is not a lookup revive points to, and `go install` does not install it. For a project's own rule the formatters print `https://revive.run/r#proj-no-os-remove`, a documentation address that leads nowhere, which reading 13 records as a dangling reference. Clause [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is No: `specify-disable-reason` and `specify-disable-rule` resolve nowhere, online or offline. Fetched again on 2026-10-11, `https://revive.run/r/` still had no anchor for either; the site describes the two settings only in the prose of its comment-directives documentation, under no address keyed on either name (reading 11), and nothing installed resolves them. A release gate of the kind the clause asks for would have failed the release (reading 28).

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is partial. No setting switches the `//revive:disable`, `disable-line` and `disable-next-line` directives off ([README](https://github.com/revive-lint/revive/blob/v1.17.1/README.md), [`config.go`](https://github.com/revive-lint/revive/blob/v1.17.1/lint/config.go)), and revive reports nothing about what they suppress, so the route is detected only by a project rule, as `proj-no-revive-directive` did by reading `f.AST.Comments` (ran). The same route silences that rule: `//revive:disable:proj-no-os-remove,proj-no-revive-directive legacy code` hid both findings under the strictest directive settings and the run exited 0, and a bare `//revive:disable` hid the detecting rule's finding on its own line (ran). That is reading 19. The `-exclude` flag, per-rule `Exclude` lists, `Disabled` and the confidence threshold select rules, their severity or the files a run covers, which is configuration and not a route (reading 29); revive reads no file of accepted findings. A file headed `// Code generated ... DO NOT EDIT.` is skipped unless the configuration sets `ignore-generated-header = true` ([`linter.go`](https://github.com/revive-lint/revive/blob/v1.17.1/lint/linter.go#L150), [README](https://github.com/revive-lint/revive/blob/v1.17.1/README.md)), so that comment is a route too, disableable by a documented setting (reading 17).

Two behaviours outside every clause. By default revive exits 0 with findings; `-set_exit_status`, or `errorCode` and `warningCode` in the configuration, makes it fail. Under reading 9, a file that does not parse is printed as a finding with an empty rule name, `bad.go:3:9: invalid file bad.go: ...`, and exits 0 unless `-set_exit_status` is given, when it exits 1 like any finding (ran).

The detector grade is 🟡: no structural MUST is No, and the MUSTs not met in full are [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code), [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) and [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable). Readiness is 🟡: bespoke rules are supported, but one rule runs alone only through a configuration and the default output omits the identifier.

## Notes for a practitioner

Write the class as a `lint.Rule` with a stable name, build the project's revive binary around `cli.RunRevive` with it, and prove it red with a configuration that enables that rule and disables every other extra rule, run against the originating file. Run the enforced invocation with `-formatter unix` or `json` so that every finding carries its rule name, and with `-set_exit_status` so that a finding fails the build. Enable `[directive.specify-disable-reason]` and `[directive.specify-disable-rule]` from the start. A project that forbids the directives can write a rule over comments, as above, but must back it with a text search outside revive, because a directive naming that rule silences it. To look a bundled rule up offline, keep a copy of the [rule descriptions](https://github.com/revive-lint/revive/blob/v1.17.1/RULES_DESCRIPTIONS.md) at the pinned version, since revive installs none.
