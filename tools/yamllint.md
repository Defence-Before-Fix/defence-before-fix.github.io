# yamllint

{% include tool-grades.html %}

yamllint is the general linter for YAML files, in Python: beyond checking that a file parses, it reports duplicate keys, truthy values such as `yes`, octal and float spellings, and layout such as indentation, line length and spacing, through 23 rules each named by an id such as `truthy` or `key-duplicates`. A project configures it from `.yamllint` and runs it over every YAML file, often before a schema check or a tool that understands the file's meaning, such as actionlint or ansible-lint. It is a fixed-catalogue detector: a project enables, disables and tunes the rules and cannot add one.

## How it is conformant

Every finding carries its rule's id, set once as the module's `ID` constant: `2:6 warning truthy value should be one of [false, true] (truthy)` in `standard`, `colored` and `auto`, `a.yml:2:6: [warning] ... (truthy)` in `parsable`, and `::warning file=a.yml,line=2,col=6::2:6 [truthy] ...` in `github` (ran, version 1.38.0). Brackets and parentheses delimit the id rather than join to it, so it is printed unaltered under reading 6, in all five formats `--help` lists, of which `parsable` and `github` are the ones meant for another tool to read ([4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding)). Because yamllint fails [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it), clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is graded on the bundled rules.

`yamllint a.yml` runs locally on one file, and `-` reads standard input ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file), ran); the findings are the command's own output, with exit 1 on an error-level finding ([5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran)), and nothing is held back for a service or tier ([5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)). A YAML syntax error is reported as a finding, `3:1 error syntax error: expected ',' or ']', but got '<stream end>' (syntax)`, with exit 1 (ran), so an unparseable file does not pass. Exit codes are set in [`cli.py`](https://github.com/adrienverge/yamllint/blob/v1.38.0/yamllint/cli.py): 1 on errors, 2 on warnings only under `--strict`, otherwise 0, and 255 (`sys.exit(-1)`) when a file cannot be read (ran).

## How it is not conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) fails. [`yamllint/rules/__init__.py`](https://github.com/adrienverge/yamllint/blob/v1.38.0/yamllint/rules/__init__.py) imports 23 named modules into a fixed `_RULES` table and `get()` raises `no such rule` for anything else; there are no entry points, and the [configuration](https://github.com/adrienverge/yamllint/blob/v1.38.0/docs/configuration.rst) only enables, disables and tunes those rules or `extends` another configuration. Clause [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) fails: nothing enforces [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), and where a project can write no rules at all that is No, not Not applicable (reading 7). With no rule of the project's own, [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is asked of the bundled rules alone; reading 20 is for a project whose rules cannot carry an identifier, not one that has none.

Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is partial. No option selects one rule; the route is a configuration written for it, `yamllint -d '{rules: {truthy: enable}}' a.yml`, which printed only the `(truthy)` finding (ran), the case of readings 4 and 21.

Resolution fails. Each rule's documentation is the docstring of its module, installed with the package, and the online [rules page](https://github.com/adrienverge/yamllint/blob/v1.38.0/docs/rules.rst) is built from those docstrings with `automodule`. yamllint prints no documentation address with a finding, its documentation states no lookup form, and it has no command that shows a rule's text (`--list-files` lists files); a docstring in a source file is not documentation under reading 12 unless a mechanism of the detector's own presents it. There is no mechanism, so [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fail. With nothing the detector provides landing any id on a page, 1.38.0 shipped ids whose documentation resolves nowhere, and a gate of the kind [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) asks for would have failed it (reading 28).

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fails for the inline routes. `# yamllint disable-line`, `# yamllint disable-line rule:<id>`, `# yamllint disable` with `# yamllint enable`, and `# yamllint disable-file` on the first line are matched by fixed patterns in [`linter.py`](https://github.com/adrienverge/yamllint/blob/v1.38.0/yamllint/linter.py) and [documented](https://github.com/adrienverge/yamllint/blob/v1.38.0/docs/disable_with_comments.rst), with no setting that turns them off, and yamllint cannot host a rule that would see them. In a run, `# yamllint disable-file` silenced a file with exit 0, and a `disable-line rule:colons` on a line with no colon problem was accepted without remark (ran). No reason is asked for on a directive, and none can be given on its line: the patterns allow nothing after the `rule:` list, so `# yamllint disable-line rule:truthy reason: legacy` matched nothing and the finding was printed (ran) ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)). The configuration's `ignore` and per-rule `ignore` patterns list paths, which is configuration and not a route (reading 29), but they hide what they cover without a sign: a per-rule `ignore: [a.yml]` on `truthy` dropped that finding, and a top-level `ignore: [a.yml]` printed nothing at all, each with exit 0 (ran).

Readiness is 🔴 because no bespoke rule can be written. The detector grade is 🔴 because [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) fails, a structural MUST under reading 1; [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is partial, and [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) and [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fail. yamllint declares no version of this document.

## Notes for a practitioner

Keep yamllint for its catalogue and put a project's own YAML rule in a host that takes one, such as [Spectral](spectral.md) or [ast-grep](ast-grep.md) with its YAML grammar. Prove a bundled rule on a fixture with a one-rule `-d` configuration, and use `-f parsable` where a tool reads the output. Run it with `--strict` if warnings must fail the build, since by default `truthy` and other warning-level findings exit 0. Forbid `# yamllint disable` comments with a search outside yamllint, since it will neither report nor refuse them; a reason for one has to go on a comment line of its own, because text after the directive voids it. Look a rule up by its id on the rules page, whose headings match the ids.
