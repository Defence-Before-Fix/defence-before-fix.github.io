# cpplint

{% include tool-grades.html %}

cpplint is the maintained fork of Google's `cpplint.py`, a single-file Python linter that checks C and C++ source against the Google C++ Style Guide line by line, with regular expressions over the source with comments and strings elided. Each finding carries a category such as `whitespace/braces` and a confidence from 1 to 5. In a pipeline it sits beside clang-format and clang-tidy as a quick lexical check of layout, header guards, include order and a handful of unsafe calls.

## How it is conformant

Every finding is printed with its category in brackets, `a.cc:3:  Missing space before {  [whitespace/braces] [5]`, and the category was printed unaltered in the default `emacs` output and in `eclipse`, `vs7`, `junit`, `sed` and `gsed` (ran at 2.0.2). The categories are listed in `_ERROR_CATEGORIES` ([`cpplint.py`](https://github.com/cpplint/cpplint/blob/2.0.2/cpplint.py#L297)) and chosen once by the maintainers ([4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding)). cpplint runs locally on a single file with no service, prints its findings and a total in the command's own output, and exits 1 when it finds anything; the `junit` report goes to standard error, still in the command's output, and there is no report-file option ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file), [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran), [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally); ran).

## How it is not conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) is partial. The command loads nothing of the project's: `--help` documents filters, line length, header extensions and the `CPPLINT.cfg` file, and no plugin option. The route is the library. `ProcessFile(filename, vlevel, extra_check_functions)` takes "an array of additional check functions that will be run on each source line" ([`cpplint.py`](https://github.com/cpplint/cpplint/blob/2.0.2/cpplint.py#L7518)), documented only in that docstring. A driver script of the project's own that imports `cpplint`, parses the arguments and calls `ProcessFile` with two check functions printed `p.cc:4:  gets() is forbidden  [proj/no-gets] [5]` beside the bundled findings, with the author's category unaltered and the same filters and exit code (ran). For `NOLINT(proj/no-gets)` to suppress it, and not be reported as `Unknown NOLINT error category: proj/no-gets  [readability/nolint]`, the driver also had to append its categories to the private `_ERROR_CATEGORIES` list (ran). This is the case of a rule reached only through the library, which the register grades partial, as on the actionlint page.

Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is partial. `--filter=-,+whitespace/braces` leaves only that category, and the help documents it as a filter of what is printed: "only error messages whose category names pass the filters will be printed" ([`cpplint.py`](https://github.com/cpplint/cpplint/blob/2.0.2/cpplint.py#L66)). Every check still runs, and the filter hides the rest, so it selects the output and not the rule: a print filter, which reading 21 grades Partial.

There is no rule over the rules: a check function may pass any string as its category and it is printed, registered or not (ran) ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)).

Resolution fails. `--filter=` with no argument prints the 66 bundled category names, one per line, and nothing else (ran, under `unshare -rn`), and no command, file or printed address gives a category's description; the finding's message is the only text, and a message that carries its own explanation resolves that message, not the identifier. A list of names is not documentation under reading 12, so [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fail. No category is described anywhere else either: the README and the help at the tag name categories only in examples, and the style guide cpplint follows is not keyed on them, so the release shipped identifiers whose documentation resolves nowhere, online or offline, and a gate of the kind [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) asks for would have failed it (reading 28).

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fails. `NOLINT`, `NOLINT(category)`, `NOLINTNEXTLINE` and `NOLINTBEGIN` with `NOLINTEND` are documented in `--help` with no setting that turns them off. A project check function sees the raw line, and one that reports any `NOLINT` printed `NOLINT is forbidden here  [proj/no-nolint]`, but a bare `// NOLINT` or `// NOLINT(*)` on the same line silenced both it and the finding it was meant to expose (ran), so the inline route is detected only in part (reading 19). The bundled `readability/nolint` reports only a malformed directive or an unknown category, and a `NOLINT(whitespace/braces)` that suppressed nothing exited 0 without remark (ran). The second route is a filter naming a category at a line. A filter may be limited to a file and a line, `category:file:line`, as `--help` documents ("Filters can directly be limited to files and also line numbers", [`cpplint.py`](https://github.com/cpplint/cpplint/blob/2.0.2/cpplint.py#L141)), and a `CPPLINT.cfg`, read from the file's own directory and every directory above it, takes the same `filter=` lines: one holding `filter=-whitespace/braces:sub/a.cc:2` hid the finding at line 2 and kept the one at line 4, and the run printed `Total errors found: 1` and nothing about the entry (ran). An entry naming a rule at a line is a route under reading 29, wherever the detector reads it from. A `filter=` that turns a category off for the directory, such as `filter=-whitespace`, which removed two findings from a file there unreported (ran), is configuration and not a route (reading 29), but it too hides findings without a sign. The same per-line filter on the command line applies only where the command names it, so it is disableable (reading 17); in `CPPLINT.cfg` it applies whenever the file exists, `--config=filename` only changes the name searched for, which does not disable the route (reading 17), and nothing reports what it hid, so that route is neither disableable nor detectable (readings 16 and 18), and the row is No on it alone. `exclude_files` is reported (`Ignoring "sub/a.cc": file excluded by ...`) and is configuration in any case. No reason is asked for on any directive ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)).

A file cpplint cannot read stops it from defending without a sign (reading 9): `nofile.cc` printed `Skipping input 'nofile.cc': Can't open for reading` and exited 0. There is no parse step to fail: a binary file and a file with an unterminated string were linted line by line, exit 1 (ran).

Readiness is 🟡: a bespoke rule and a single-rule run need the driver and the filter workarounds, and the identifier is printed. The detector grade is 🟡 because no structural MUST is No: [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) and [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) are partial, and [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) and [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fail, with the SHOULDs [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own), [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) and [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) not met. cpplint declares no version of this document.

## Notes for a practitioner

cpplint is a style checker first; put a project's own C or C++ rule in a host that registers one, such as [clang-tidy](clang-tidy.md) or [Cppcheck](cppcheck.md) addons, unless the rule is a line-level text pattern and the project is content to keep a driver script that calls `ProcessFile` with its check functions and appends its categories to `_ERROR_CATEGORIES`. Prove a check with `--filter=-,+<category>` on a fixture. Forbid `NOLINT` and `CPPLINT.cfg` with a search outside cpplint, since a check inside it is silenced by a bare `NOLINT` on the same line and nothing in it reports a `CPPLINT.cfg` filter; put `set noparent` in the top-level `CPPLINT.cfg` so that no file above the repository applies. Look a category up in the style guide by its message, since cpplint ships nothing keyed on the category. Check that every file passed was read, since an unreadable file exits 0.
