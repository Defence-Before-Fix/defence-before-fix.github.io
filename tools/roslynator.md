# Roslynator

{% include tool-grades.html %}

Roslynator is a set of C# analyser packages, `Roslynator.Analyzers` with the `RCS1` rules and `Roslynator.Formatting.Analyzers` with the `RCS0` rules (both version 5.0.1), and a command-line tool, `Roslynator.DotNet.Cli` version 1.0.1, which loads a project or solution and runs analysers over it outside a build. The packs run on the [Roslyn host](roslyn-analyzers.md) in an ordinary `dotnet build`, and most of their rules are off or at the info or hidden level by default (ran: 187 of the 270 descriptors are info and 67 hidden), so a project raises the ones it wants in `.editorconfig`. This page grades what Roslynator adds to the host: the two packs and the `roslynator analyze` command.

## How it is conformant

`roslynator analyze` runs a project's own rule with the standing of the packs' rules (4.1). It runs the analysers the project references, and `-a`/`--analyzer-assemblies` adds any other analyser assembly ([options at the tag](https://github.com/dotnet/roslynator/blob/cli-v1.0.1/src/CommandLine/Options/AbstractAnalyzeCommandLineOptions.cs)); the CLI bundles none of its own (ran: with `--ignore-analyzer-references` it printed "No analyzers found"). Ran: a project `DiagnosticAnalyzer` passed with `-a` printed `A.cs(17,42): warning PROJ0001: Read the clock through IClock, not DateTime.Now` beside `B.cs(8,50): warning RCS1080: Use 'Count' property instead of 'Any' method`, and both were counted in the summary. `--supported-diagnostics <id>` reports one identifier alone (4.2; ran with `PROJ0001`, which printed only that finding). The identifier is the descriptor's, assigned once and printed unaltered on the console, as `ruleId` in the SARIF version 2.1.0 file, as `check_name` in the GitLab file and as `Id` in the XML file (4.3, ran in each).

The command runs locally with no service (5.1; ran with the network removed). It needs a project or solution, and `--include <glob>` restricts the analysis to the files it matches (5.2; ran, `--include B.cs` reported only `B.cs`). The packs also run in `dotnet build` of a one-file app with `#:package Roslynator.Analyzers@5.0.1` (ran). Every finding prints on the console with a count per identifier, and with `-o` the file is written as well, the console unchanged at the default verbosity (5.3, ran). Nothing is held back for a service or licence tier (5.4).

Clause 7.1 holds. The routes are the host's: `#pragma warning disable`, the `SuppressMessage` attribute and the generated code header. `--report-suppressed-diagnostics` reports what the first two hid ([options](https://github.com/dotnet/roslynator/blob/cli-v1.0.1/src/CommandLine/Options/AnalyzeCommandLineOptions.cs)). Ran: a file with one pragma-hidden `RCS1080` gave 2 findings by default and 3 with the flag. The suppressed finding is listed like any other, so seeing which one it was means comparing the two runs. A `// <auto-generated/>` header hid a file's `RCS1080` even with that flag, and `generated_code = false` in `.editorconfig` brought it back (ran). The host's SARIF log from `dotnet build` records the pragma and attribute suppressions as well, as on the [Roslyn host](roslyn-analyzers.md) page.

## How it is not conformant

Resolving an identifier is partial (6.1). Each `RCS` descriptor carries `https://josefpihrt.github.io/docs/roslynator/analyzers/<id>`, keyed on the identifier exactly as printed. `dotnet build` prints that address after the message, and the XML file of `roslynator analyze` carries it as `HelpLink`. The CLI's console line and its SARIF file carry no address (ran). Ran: all 246 `RCS` addresses answered 200 after a redirect to the same address with a trailing slash. Two kinds of bundled identifier resolve to nothing. `ROS0003`, "Analyzer requires config option to be specified", links to the index page `analyzers/`, and its own address answered 404. The 23 `FadeOut` identifiers, such as `RCS1032FadeOut`, carry no address, and the [descriptor factory](https://github.com/dotnet/roslynator/blob/v5.0.1/src/Common/DiagnosticDescriptorFactory.cs) declares them hidden and `NotConfigurable`. A build never prints them, but `roslynator analyze --severity-level hidden --report-not-configurable` did: `hidden RCS1032FadeOut: Remove redundant parentheses`. The address with that identifier answered 404.

Nothing resolves offline (6.2, 6.3). Ran: each package's `docs/README.md` names no identifier, and the packages and the tool ship no page for any. No release gate over rule documentation was found in the [build workflow at the tag](https://github.com/dotnet/roslynator/blob/v5.0.1/.github/workflows/build.yml) (6.4). There is no rule over the identifiers of a project's analyser (4.4). `Roslynator.CodeAnalysis.Analyzers` has rules for analyser authors, `RCS9001` to `RCS9011` at the tag, but none of them concerns a descriptor's identifier ([`Analyzers.xml`](https://github.com/dotnet/roslynator/blob/v5.0.1/src/Analyzers.xml)). No reason is asked of a suppression (7.2).

The detector grade is 🟡: no structural clause fails, and 6.1, 6.2 and 6.3 are the MUSTs that do not hold in full. Readiness is 🟢: a project's analyser runs in the command, one identifier runs alone by a flag, and the identifier prints with every finding.

## Notes for a practitioner

Write the defence as a Roslyn analyser of the project's own, reference it from the project, and prove it with `roslynator analyze --supported-diagnostics <id> --include <file>`. Check the summary line: a misspelt identifier given to `--supported-diagnostics` printed "No analyzers found" and "0 diagnostics found" and exited 0 (ran), so a typo looks like a pass. A descriptor marked `NotConfigurable`, which is how a rule that forbids suppressions is kept from being suppressed on the host, is not reported by `roslynator analyze` unless `--report-not-configurable` is given (ran). At `-v m` the console carries only the count, with neither the findings nor their identifiers. Compiler errors are reported as findings by default, so a file that does not parse fails the run; with `--ignore-compiler-diagnostics` the same file gave "0 diagnostics found" and exit 0 (ran). Set `generated_code = false` for the project's own sources.
