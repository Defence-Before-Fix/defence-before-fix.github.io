# py-qa-ci

{% include tool-grades.html %}

py-qa-ci, called python-qa-ci before its 0.2.0 release, is one QA entry point for Python projects, installed as a development dependency from a pinned tag and run as `py-qa run` ([repository](https://github.com/LongTermSupport/py-qa-ci)). It runs a format lane, then py-qa's own detector lanes (the project record, the suppression scan, the agent summary and the documentation check), Ruff, mypy, Pylint as the host for bespoke rules and any check the project declares, then the tests under coverage. Beside the run it ships `py-qa rules`, `py-qa rule-doc <identifier>`, `py-qa rule <identifier> <path>`, `py-qa record` and `py-qa summary`.

Every mechanism below was checked by running it under Python 3.13 in a probe project that installed the release with `uv add --dev "py-qa-ci @ git+https://github.com/LongTermSupport/py-qa-ci@v0.4.1"`, as its README directs, and in a checkout of the release itself. The probe carried a Pylint rule of its own, `proj-no-legacy-send` (`W9901`), written as the README's "Writing rules" shows, and a project check, `proj-no-todo`. Detector conformance is graded on the detectors the toolchain routes a defence through, each together with the wrapping around it, as toolchain clause [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification) requires. Toolchain conformance grades the artefact a consuming project installs. Project conformance grades the repository as a project following the method with the toolchain it ships.

## Tools it bundles

py-qa-ci pins Ruff 0.16.10, mypy 2.4.0 and Pylint 4.1.2 exactly and pytest and coverage.py as floors ([`pyproject.toml` at v0.4.1](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/pyproject.toml)). For each lane: whether it can host a bespoke defence, and which of the toolchain's mechanisms wrap it.

- **fmt: `ruff format`, or Black.** A formatter, run as a check under `--no-fix`, `--ci` or a set `CI` variable, failing as `pyqaci.format`; cannot host a defence. A `# fmt: off` region is left unformatted and is not held to the record (ran), which is the formatter's business rather than a defence's.
- **record, suppression, summary, docs: py-qa's own lanes.** Bundled defences of the toolchain's own, `pyqaci.record.*`, `pyqaci.suppression.*`, `pyqaci.summary.stale` and `pyqaci.docs.dangling`, each listed, documented on a shipped page and resolved by `py-qa rule-doc`. A project adds a rule here with `[[tool.py-qa.check]]`: a script of its own that becomes a lane named by the check's `name`, run in the detector phase, listed, documented from its `doc` file and delivered into the agent summary, so py-qa hosts bespoke rules in its own lanes as well as in Pylint.
- **ruff: `ruff check`.** Runs the project's Ruff configuration, or the bundled hazard-focused selection, whose 562 rules `py-qa rules` lists as active defences, each with its own identifier and route, and the agent summary says "also block". Ruff cannot host a bespoke rule. Wrapped by `py-qa rule` (`--select=<code>`), `py-qa rule-doc` (`ruff rule <code>`) and `py-qa rules` (`ruff check --show-settings`).
- **mypy.** Runs the project's mypy configuration, or the bundled `strict` one with five extra error codes, whose 70 enabled codes `py-qa rules` lists as active defences. Hosts a project's code only through mypy plugins in the project's own configuration. Wrapped by `py-qa rule-doc` (the installed `mypy.errorcodes`) and `py-qa rules`; `py-qa rule` refuses a mypy code.
- **pylint.** The bespoke rule host: py-qa runs it with its own rcfile, `--disable=all`, and only the bundled plugin's messages, the project plugins' messages and any Pylint message named in `pylint_enable`. Wrapped by all three commands.
- **test: pytest under coverage.py, or the project's test command.** Runners; `pyqaci.tests` and `pyqaci.coverage` name a failure. Cannot host a defence.
- **audit: pip-audit.** Off by default; needs the network. Not a host.

## How it is conformant

Readiness is green. A project's Pylint checker is registered by naming its module under `pylint_plugins` (detector [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)); `py-qa rule proj-no-legacy-send tests/fixtures/send_used.py` printed the finding and exited 1, and on a file without the call exited 0, and the command runs Pylint with `--disable=all` and `--enable=<symbol>` alone, so the one rule runs and no other does ([`tools.py` at v0.4.1](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/src/py_qa/tools.py), `pylint_commands`), which reading 4 counts as a harness (detector [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)); and Pylint printed `W9901: legacy_send() bypasses the outbox ... (proj-no-legacy-send)`, the message id and symbol the author chose, unaltered (detector [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding)). The same command runs one Ruff code alone with `--select=<code>`: `py-qa rule B006` on a file holding a mutable default and a `print` reported B006 and not T201 (ran).

Section [5](../TOOLING-SPEC.md#5-enumeration) of the detector specification holds for the shipped lanes. `py-qa run -p <file>` narrowed the format, Ruff, mypy, Pylint and suppression lanes to that file (mypy "checked 1 source file", ran), every tool writes to the terminal, and the wrapping passes neither Pylint's `--output` nor Ruff's `--output-file`, so the report-file gaps on [the Pylint page](pylint.md) and [the Ruff page](ruff.md) do not arise as wrapped (reading 3). CI runs the same `uv run py-qa run` ([`ci.yml` at v0.4.1](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/.github/workflows/ci.yml)). A file that cannot be parsed failed every source lane with exit 1, Ruff with `invalid-syntax`, mypy with `[syntax]` and Pylint with `E0001 (syntax-error)` (ran; reading 9).

`py-qa rule-doc` resolves an identifier exactly as printed, from the installed copy: a bundled `pyqaci.*` identifier or bundled Pylint message to its shipped page under `src/py_qa/docs/rules/`, by symbol or message id; a project's rule by its symbol to `docs/defences/<symbol>.md`; a project check to its description and `doc` file; any Pylint message to its description from the loaded message store; a Ruff code to `ruff rule <code>`; a mypy code to the description mypy ships in `mypy.errorcodes`; and a suppression route such as `mypy::disallow_untyped_defs` to a page of its own ([`docs.py` at v0.4.1](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/src/py_qa/docs.py)). Inside a network namespace with no route out, `proj-no-legacy-send`, `pyqaci-broad-suppress`, `S602`, `W0611`, `return-value` and `pyqaci.record.invalid` each printed their documentation (ran). That closes for the toolchain what mypy alone fails, since mypy's own pages are online only ([the mypy page](mypy.md)); every one of the 78 codes the installed mypy defines, read from its source, is in `mypy.errorcodes` and resolves, to one line each, which reading 12 counts as documentation and whose brevity is recorded here. The bundled pages are held by [`test_docs.py`](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/tests/py_qa/test_docs.py): every `pyqaci.*` identifier and bundled Pylint message has a page with `## What it flags`, `## Why` and `## How to fix correctly`, and every page belongs to one; the `docs` lane fails a project rule or check whose page is missing or incomplete (ran: `pyqaci.docs.dangling proj-no-legacy-send has no documentation page` before the page was written).

The suppression lane reads every Python file git does not ignore with `tokenize` and holds each suppression comment to the record by tool and identifier: `noqa`, `ruff: noqa`, `ruff: disable[...]` and the isort action comments for Ruff; `pylint: disable=`, `disable-next=`, `disable-line=` and `skip-file` for Pylint; `type: ignore[...]` and file-level `mypy:` settings for mypy; and the Pyright, Bandit, Semgrep and coverage.py forms ([`suppression.py` at v0.4.1](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/src/py_qa/suppression.py)). In the probe, `# pylint: disable=proj-no-legacy-send`, `# noqa: T201` and `# type: ignore[return-value]` were each reported as `pyqaci.suppression.unrecorded`, and `# pylint: skip-file` as `pyqaci.suppression.blanket` (ran). Ruff's comment routes, which Ruff alone documents as neither disableable nor seen, are therefore seen as wrapped, and Pylint's own configuration is never read, since py-qa passes its own rcfile. Every route the lane sees needs a record exception with a checked justification, so as wrapped those routes require a written reason (detector [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason), in part; below). Neither Pylint nor mypy skips a file for a generated-code marker (none in their installed sources, searched), so reading 29 adds no route.

At toolchain level, `py-qa rules` lists every active defence without running it, each with its identifier, tool, origin, a one-sentence summary and `py-qa rule-doc <identifier>` as its route: in the probe, eleven `pyqaci.*` defences, the project check, the project Pylint rule, the two bundled Pylint rules, 562 Ruff codes and 70 mypy codes, then the record beneath, then the `scan_exclude` globs (toolchain [5.1](../TOOLING-SPEC.md#51-the-toolchain-must-be-able-to-list-the-defences-active-in-a-project-without-triggering-them), [5.3](../TOOLING-SPEC.md#53-a-projects-own-defences-must-appear-in-the-listing-alongside-bundled-ones) and [6.3](../TOOLING-SPEC.md#63-the-project-record-must-be-enumerable-by-the-same-means-as-the-defences), ran). It is derived from the loaded Pylint checkers, `ruff check --show-settings`, mypy's parsed options and the check tables ([`defences.py` at v0.4.1](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/src/py_qa/defences.py); toolchain [5.2](../TOOLING-SPEC.md#52-the-listing-must-be-derived-from-the-active-configuration)), and a project rule's page lives at `docs/defences/<symbol>.md`, whose three sections the `docs` lane requires (toolchain [4.2](../TOOLING-SPEC.md#42-the-toolchain-must-resolve-every-identifier-a-defence-it-routes-can-print-from-the-installed-copy-without-network-access), the place to live). The record is `qa/record.toml`, loaded by every run (toolchain [6.1](../TOOLING-SPEC.md#61-the-toolchain-must-define-a-location-for-the-project-record-and-must-read-it-itself)). An exception justified "legacy, needed for now, TODO revisit this later on please" failed with `pyqaci.record.invalid ... justification is generic or too short; name the hazard accepted and the scope`, and one naming the hazard and scope passed and was listed by `py-qa rules` with its justification (ran; toolchain [6.2](../TOOLING-SPEC.md#62-every-exception-in-the-project-record-must-carry-a-written-justification-that-names-the-hazard-and-the-scope-and-the-toolchain-must-reject-a-generic-one)). The README states the defaults for the record, the pages, the sweep scope, fixtures, the hazard and the calibrations (toolchain [6.4](../TOOLING-SPEC.md#64-the-toolchain-should-state-its-own-defaults-for-anything-the-method-leaves-to-the-project)). The detector lanes run before the runners, and a detector failure printed `py-qa: runners not run: a format or detector lane failed` (ran; toolchain [4.5](../TOOLING-SPEC.md#45-the-toolchains-entry-point-must-run-detectors-before-runners-and-must-stop-on-a-detector-failure)). The declaration is `[tool.defence-before-fix]` in `pyproject.toml`, method 1.1.0, detector 1.0.0 and toolchain 0.2.0, with `[tool.defence-before-fix.project]` beside it, each with two `known-gaps`, against toolchain [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification) and [4.2](../TOOLING-SPEC.md#42-the-toolchain-must-resolve-every-identifier-a-defence-it-routes-can-print-from-the-installed-copy-without-network-access), so neither level claims conformance (toolchain [9.1](../TOOLING-SPEC.md#91-a-project-that-ships-a-detector-or-a-toolchain-has-two-levels-of-conformance-graded-separately) and [9.2](../TOOLING-SPEC.md#92-the-declaration-is-the-claim-and-the-known-gap-record-not-a-condition-of-conformance)).

## How it is not conformant

Reading 3 decides the detector column: clause by clause it takes the lowest over the detectors the toolchain routes a defence through, each as wrapped. Those are Pylint, Ruff, mypy and py-qa's own lanes, the project checks among them. Ruff and mypy are among them because the toolchain carries their rules as defences: the default selection is enabled in every consuming project without a configuration of its own, blocks, resolves through `py-qa rule-doc` and is listed rule by rule as active, which is a bundled defence as toolchain section [2](../TOOLING-SPEC.md#2-terminology) defines one; the declaration's own [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification) gap says the opposite, "no defence is routed through them", and the register takes the reading fewer tools meet. Ruff "cannot host a bespoke rule at all", in the words of toolchain [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification), and no wrapping lets a project add one to the Ruff lane, so detector [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) is No for Ruff as wrapped, structural under reading 1, and the detector grade is red. Toolchain [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification) fails with it, as declared.

The other detector rows that fall short are these. Detector [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is Partial: `py-qa rule return-value` stopped with `py-qa cannot run one rule alone for this identifier` and exit 2, so a mypy code runs alone only under a configuration disabling every other, as on [the mypy page](mypy.md) (reading 4); a suppression rule is answered by running the whole scan and keeping that rule's findings ([`cli.py` at v0.4.1](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/src/py_qa/cli.py), `_rule`; reading 21); a record or documentation rule is refused ("it reads no source"), and a project check is refused too, reachable alone only as `py-qa run -t <name>` over its own scope. The harness also takes only files in the sweep scope, and the README's default for fixtures, "files under `tests/fixtures/`, kept out of the sweep with `scan_exclude`", puts them out of reach: with that setting, `py-qa rule proj-no-legacy-send tests/fixtures/send_used.py` stopped with `no Python file under tests/fixtures/send_used.py`, and `py-qa rule pyqaci.suppression.unrecorded` on a fixture there holding an unrecorded `type: ignore[return-value]` exited 0 as though it had not fired, whilst the same file outside `scan_exclude` fired (all ran). Detector [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is Partial: a project check's name is printed once when its lane fails (`py-qa: proj-no-todo failed: proj-no-todo (py-qa rule-doc proj-no-todo)`), not beside each finding the check prints (`src/probe/other.py: TODO marker`, ran). Detector [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is No: nothing checks a Ruff or mypy rule for an identifier, whilst Pylint refuses a malformed message id at load and py-qa refuses a check without a `name` at load ([`config.py` at v0.4.1](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/src/py_qa/config.py)), both by construction (reading 7). Detector [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file) is Partial: under `py-qa run -p src/probe/core.py` the `proj-no-todo` check ran over the whole of `src/` and failed on another file (ran), since `-p` is passed to no check; a check reaches only changed files, and only through a `diff_command` the project writes, so it names a single file for the shipped lanes and for a project check through configuration alone (reading 22).

Ruff's `invalid-syntax`, printed by the Ruff lane on a file it cannot parse, resolves to nothing: `py-qa rule-doc invalid-syntax` printed `no documentation for invalid-syntax` and exited 1, online and offline (ran), as `ruff rule` fails it on [the Ruff page](ruff.md). Detector [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) and [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) are therefore Partial and detector [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) is No (readings 14 and 27). The release shipped that identifier landing on no page, and `test_docs.py` checks the bundled `pyqaci` pages and samples one identifier of each native catalogue, so detector [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is No (reading 28).

Detector [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is No through mypy. `@typing.no_type_check` on a function declared `-> int` that returns a `str` gave a run with every lane passing and the record empty, and without the decorator mypy failed it with `return-value` (both ran). The decorator is an annotation in the checked code that silences findings there (reading 29); nothing switches it off, the suppression lane does not look for it, and a mypy plugin's function hook on `typing.no_type_check`, which fired on `typing.no_type_check(len)` called directly, did not fire on the decorator (ran), so the route is neither disableable nor detectable (reading 16). Pylint's inline route is seen only in part: Pylint honours a pragma anywhere in a comment, but the lane reads one only at the start of a comment segment, so `legacy_send(text)  # outbox is down here, so pylint: disable=proj-no-legacy-send` gave a passing run with the record empty, and the same line without the comment failed the Pylint lane (both ran). A rule of the project's own in Pylint could see that comment, but the same pragma naming that rule would silence it (reading 19). Neither of these routes asks for a reason, so detector [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) is Partial (reading 30).

Toolchain [4.3](../TOOLING-SPEC.md#43-the-toolchain-must-forbid-through-a-defence-of-its-own-every-suppression-route-that-bypasses-the-project-record) fails on the same two runs: a finding was silenced through each without an entry in the project record and without any lane failing, and `known-gaps` does not name either. Toolchain [4.4](../TOOLING-SPEC.md#44-the-toolchains-own-invocation-must-satisfy-the-detector-specifications-reporting-clauses-for-every-defence-it-routes) fails on the project check: the entry point reaches one file for the shipped lanes, but `-p` does not narrow a project check, which then reports on files the practitioner did not name. Toolchain [4.2](../TOOLING-SPEC.md#42-the-toolchain-must-resolve-every-identifier-a-defence-it-routes-can-print-from-the-installed-copy-without-network-access) is Partial: a project rule resolves by its symbol, but not by the message id Pylint prints beside it. `py-qa rule-doc W9901` printed `no documentation for W9901` with the plugin at the project root and again with it under `src/`, the two places the README says a plugin is imported from, because the resolver loads the project's plugins without the project's import paths, whilst `py-qa rules` and the Pylint lane load them with those paths ([`docs.py`](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/src/py_qa/docs.py), `_pylint_definitions`, against [`tools.py`](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/src/py_qa/tools.py), `pylint_messages`). A bundled message id, `W9701`, resolves, because the bundled plugin is installed. The declared [4.2](../TOOLING-SPEC.md#42-the-toolchain-must-resolve-every-identifier-a-defence-it-routes-can-print-from-the-installed-copy-without-network-access) gap is that a mypy code resolves only to mypy's one line, which states no correct construction.

Two settings hide findings without a sign in the record, which reading 29 counts as configuration rather than suppression routes. Ruff reads the closest configuration file to each source file and follows a configuration's `extend`, but the suppression lane reads only `pyproject.toml`, `ruff.toml` and `.ruff.toml` at the root: a `src/probe/sub/ruff.toml` ignoring T201, and a `qa/ruff-base.toml` named by `extend` doing the same, each let a `print` through with every lane passing, where without the ignore the Ruff lane failed (all ran). And `scan_exclude`, which the README suggests for fixtures, takes files out of the suppression scan and the Pylint pass whilst Ruff and mypy still read them, so a `# noqa: T201` in a file it covers silenced Ruff with no record entry (ran); `py-qa rules` lists the globs.

The SHOULDs and self-audit fall short in places. The agent summary writes one standing instruction per `pyqaci.*`, Pylint and check defence, then "562 Ruff rules and 70 mypy error codes also block; `py-qa rules` lists every one" (ran), so toolchain [7.1](../TOOLING-SPEC.md#71-the-toolchain-should-generate-a-summary-of-the-active-defences-suitable-for-an-agents-context) is Partial; it is written into a delimited region of the file `[tool.py-qa.summary] file` names, off until that is set, and refreshed only by running `py-qa summary`, the `summary` lane failing when it is stale, so toolchain [7.2](../TOOLING-SPEC.md#72-the-toolchain-should-deliver-that-summary-into-the-project-automatically) is Partial, as the toolchain's own [conformance record](https://github.com/LongTermSupport/py-qa-ci/blob/v0.4.1/docs/CONFORMANCE.md) says. CI runs the whole pipeline on the package's own source with no Ruff or mypy configuration of its own, so the bundled defaults, the bundled Pylint plugin and the suppression scan all run there (ran in the checkout: every lane passed, 375 tests), but nothing fails the release if that run stops covering a bundled rule, such as a `pylint = false` switch or a `[tool.ruff]` table added to `pyproject.toml`, and no test looks for it, so toolchain [8.2](../TOOLING-SPEC.md#82-a-shipped-toolchain-must-run-its-own-bundled-defences-on-its-own-source) is Partial.

Project conformance carries the toolchain's gaps, because the repository runs the toolchain it ships. Its record is empty (`Project record (qa/record.toml): 0 exceptions`), it declares no project check, so the one [4.4](../TOOLING-SPEC.md#44-the-toolchains-own-invocation-must-satisfy-the-detector-specifications-reporting-clauses-for-every-defence-it-routes) gap does not reach its own run, its rules are the bundled ones, each with a `CheckerTestCase` test, and its `AGENTS.md` carries the summary region, which the `summary` lane held current in the run above. Under reading 3 the toolchain and project columns are graded on the clauses of their own document, so the red detector column counts there through toolchain [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification) alone; most toolchain MUSTs hold, so both columns are amber, with the failing clauses named above.

## Notes for a practitioner

Install the release as the README shows, write the defence as a Pylint checker with a message id in a range of your own and a symbol outside the `pyqaci-` prefix, list its module under `pylint_plugins`, and write `docs/defences/<symbol>.md` with its three sections, since the `docs` lane fails without it. Prove it with `py-qa rule <symbol> <fixture>`, which runs that message alone, but keep the fixture out of `scan_exclude`, or the harness cannot reach it; look a finding up by its symbol, since `py-qa rule-doc <message id>` finds a project rule only when its plugin is installed in the environment. Run `py-qa rules` first on any project you arrive at: it lists every defence and every recorded exception together. Search for `no_type_check` and for `pylint:` anywhere in a comment in review, since the suppression lane misses both; keep Ruff configuration in the root files the lane reads, since a nested `ruff.toml` or an `extend`ed file can ignore a rule unseen; and expect `-p` to leave a project check running over its whole scope.
