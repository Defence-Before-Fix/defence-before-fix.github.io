# OpenRewrite

{% include tool-grades.html %}

OpenRewrite is a refactoring engine: it parses a project into a lossless syntax tree with type attribution, runs recipes over it, and either rewrites the code or, in a dry run, reports which recipes would change which files. Search recipes mark what they find instead of changing it, so a dry run with `failOnDryRunResults` set is a check that fails the build on a finding. It runs through its Maven or Gradle plugin as a step of the build; this page grades the Maven plugin. Releases after rewrite 8.90.4 and plugin 6.46.1 are published only to the Code Genome Project repository, which needs a sign-in token to download a jar (a jar request without one returned 401, ran; [Gradle plugin configuration](https://docs.openrewrite.org/reference/gradle-plugin-configuration)), so this page grades the latest plugin on Maven Central, 6.46.1, with the rewrite 8.89.0 it pins.

## How it is conformant

A project's own recipe has the standing of a bundled one (4.1). Ran: a declarative recipe in `rewrite.yml`, `proj.no-system-exit`, composing the bundled `FindMethods` with a method pattern, and a Java recipe extending `Recipe` in an artefact of the project's own added to the plugin's dependencies, both marked every `System.exit` call in a dry run ([recipe authoring](https://docs.openrewrite.org/authoring-recipes)). One recipe runs alone with `-Drewrite.activeRecipes=<name>` ([Maven plugin](https://docs.openrewrite.org/reference/rewrite-maven-plugin)), ran for bundled and project recipes, and `RewriteTest` in `rewrite-test` is the unit harness for one recipe against before and after sources ([`RewriteTest.java` at the tag](https://github.com/openrewrite/rewrite/blob/v8.89.0/rewrite-test/src/main/java/org/openrewrite/test/RewriteTest.java)) (4.2).

The plugin runs locally with no service (5.1, 5.4); every recipe in the modules it installs, all under Apache-2.0, ran without a licence key. A dry run prints, for each file, the recipes that would change it, and the path of a patch file holding the changes, then exits 0; with `-DfailOnDryRunResults=true` the same run exits 1, ran (5.3). The property has no `rewrite.` prefix, unlike the plugin's other options ([`AbstractRewriteDryRunMojo.java` at the tag](https://github.com/openrewrite/rewrite-maven-plugin/blob/v6.46.1/src/main/java/org/openrewrite/maven/AbstractRewriteDryRunMojo.java)).

Every bundled recipe name resolves offline to a description. `rewrite:discover -Drecipe=<name> -Ddetail=true` prints the recipe's display name, its name and its description, matched on the name as printed ([`RewriteDiscoverMojo.java` at the tag](https://github.com/openrewrite/rewrite-maven-plugin/blob/v6.46.1/src/main/java/org/openrewrite/maven/RewriteDiscoverMojo.java)); ran under `unshare -rn` with Maven offline for `org.openrewrite.java.RemoveUnusedImports` and `org.openrewrite.java.search.FindMethods`, and a full `discover -Ddetail=true` listed 426 bundled recipes, every one with a description. `getDescription()` is abstract on `Recipe`, so a recipe cannot be compiled without one ([`Recipe.java` at the tag](https://github.com/openrewrite/rewrite/blob/v8.89.0/rewrite-core/src/main/java/org/openrewrite/Recipe.java)), and the description is in the recipe's own class, shipped and versioned with it. Many are a sentence or two long (reading 12).

OpenRewrite offers no inline suppression route: none is documented, and no handling of a suppression comment or annotation was found in the core modules' source. Exclusions and preconditions are configuration (7.1).

## How it is not conformant

Clause 4.3 is partial. A Java recipe's name is `getClass().getName()` unless the author overrides `getName()` ([`Recipe.java`](https://github.com/openrewrite/rewrite/blob/v8.89.0/rewrite-core/src/main/java/org/openrewrite/Recipe.java)): ran, a project recipe without the override printed `proj.UnnamedExit`, its class name, and one with it printed `proj.no-system-exit-java` unaltered. Bundled Java recipes are named by their class names, such as `org.openrewrite.java.RemoveUnusedImports`, which is the derivation the clause rules out (reading 5). A declarative recipe's `name` is chosen by its author, but run alone it was not printed on the console: the dry run named only the bundled recipe that made the change, `org.openrewrite.java.search.FindMethods: {methodPattern=java.lang.System exit(int)}`, and printed `proj.no-system-exit` only in the patch, ran; beside other recipes it was printed in the tree. In the patch, each hunk is labelled with the recipe that made it, and where several recipes were active the label was `org.openrewrite.config.CompositeRecipe` instead, ran. There is no rule over the rules (4.4).

That label decides resolution. `rewrite:discover -Drecipe=org.openrewrite.config.CompositeRecipe` failed with "Could not find recipe", ran, so a printed identifier resolves to nothing: 6.1 and 6.2 are partial (reading 14), and 6.3 fails, since "One Identifier that does not resolve fails this clause". `RewriteTest` asserts that every recipe a test runs has a description ending in a full stop ([`RewriteTest.java`](https://github.com/openrewrite/rewrite/blob/v8.89.0/rewrite-test/src/main/java/org/openrewrite/test/RewriteTest.java)), which covers the recipes that have tests; no check over every recipe was found (6.4, partial).

Clause 5.2 is partial. The plugin parses the whole project; the only way to narrow it is `-Drewrite.exclusions=<globs>`, which skips the files it names ([Maven plugin](https://docs.openrewrite.org/reference/rewrite-maven-plugin)). Excluding the second probe file left the first alone in the run, ran, but running one file means excluding every other one.

Readiness is 🟢: a bespoke recipe, a one-recipe run and an author-chosen name printed with every change all hold, once a Java recipe overrides `getName()`. The detector grade is 🟡 because of 4.3, 5.2, 6.1, 6.2 and 6.3; no structural MUST fails. A Java file that does not parse produced a warning, "There were problems parsing src/main/java/p/Bad.java", and the run exited 0 even with `failOnDryRunResults` (reading 9), ran; and a file Git ignores is not parsed at all, so in a checkout nested inside another repository whose `.gitignore` covers it, the dry run found nothing until the probe had a `.git` of its own, ran. OpenRewrite declares no version of this document.

## Notes for a practitioner

Write a defence as a Java search recipe in a recipe artefact of the project's own, override `getName()` with a project-prefixed identifier, prove it with `RewriteTest`, and run it alone with `-Drewrite.activeRecipes=<name> -DfailOnDryRunResults=true` in the gate. Run one recipe per invocation, so the console and the patch name it rather than `CompositeRecipe`, and treat "There were problems parsing" as a failure, since the exit code does not. Look a printed name up with `mvn rewrite:discover -Drecipe=<name> -Ddetail=true`, which works offline once the plugin is installed. Moving to a release after 6.46.1 means arranging access to the Code Genome Project repository, or a mirror of it, first.
