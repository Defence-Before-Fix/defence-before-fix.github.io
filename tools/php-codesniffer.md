# PHP_CodeSniffer

{% include tool-grades.html %}

PHP_CodeSniffer tokenises PHP and runs sniffs over the token stream, reporting violations of a coding standard and fixing many of them with `phpcbf`. It is usually the style gate in a pipeline, but a sniff can detect any token-level pattern, so it is a serviceable host for a bespoke defence.

## How it is conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) is met: a project defines a standard with a `ruleset.xml` and a `Sniffs` directory, and each sniff subscribes to tokens and reports through `addError` with a code of its own ([coding standard tutorial](https://github.com/PHPCSStandards/PHP_CodeSniffer/wiki/Coding-Standard-Tutorial)). Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is met by the command line: `--sniffs=Standard.Category.Sniff` restricts a run to one sniff, and a file path restricts it to one file, so a red run against a fixture needs no test suite ([advanced usage](https://github.com/PHPCSStandards/PHP_CodeSniffer/wiki/Advanced-Usage)). The flag selects rather than filters: `Ruleset` registers only the sniffs `--sniffs` names, so no other sniff runs (reading 21; [`Ruleset.php` at 4.0.4](https://github.com/PHPCSStandards/PHP_CodeSniffer/blob/4.0.4/src/Ruleset.php)), except with the result cache on, when the restriction is dropped at registration and applied to what is reported, so a red proof is run without `--cache`. Clauses [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) to [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally) hold for the same reason, [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) only in part: the run is local, takes a single file and by default prints its report to the terminal, but the documented `--report-file` option leaves the command's own output with neither a summary nor the file's name (`phpcs --standard=PSR12 --report-file=phpcs.out a.php` printed only `Time: 27ms; Memory: 6MB` and exited 1, ran at 4.0.4). Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is met because `--ignore-annotations` disables every `phpcs:ignore` and `phpcs:disable` comment, the ruleset can hard-code that flag with `<arg name="ignore-annotations"/>`, and the tokeniser exposes the annotations as their own tokens so a project sniff can detect them ([advanced usage](https://github.com/PHPCSStandards/PHP_CodeSniffer/wiki/Advanced-Usage), [annotated ruleset](https://github.com/PHPCSStandards/PHP_CodeSniffer/wiki/Annotated-Ruleset)).

## How it is not conformant

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails, and it decides the detector grade. The printed code is `Standard.Category.Sniff.ErrorCode`, and the tutorial states it is derived from the directory structure and class name, which is exactly what the clause forbids, and the clause's table grades a path-derived or class-name identifier as not stable; only the final segment is the author's to choose, and renaming the sniff file renames every reference. A project that never renames or moves a sniff keeps a working code, which is the workaround the readiness grade rests on. The code is also printed only with `-s`, which the ruleset can hard-code with `<arg value="s"/>` but the default output omits. Clause [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) fails for the bundled sniffs, which decide the row. A lookup exists and works offline: `phpcs --generator=Text --sniffs=Generic.PHP.LowerCaseConstant` prints the sniff's documentation from the `Docs/*Standard.xml` files the package ships ([generators at 4.0.4](https://github.com/PHPCSStandards/PHP_CodeSniffer/tree/4.0.4/src/Generators)). But it is keyed on the first three segments of the four-segment code, not on the identifier as printed: given the full code, `Generic.PHP.LowerCaseConstant.Found`, it refuses with "The --sniffs option only supports sniff codes" and exits 16 (both ran at 4.0.4). A mechanism that needs the printed identifier cut to a part first is keyed on something else and resolves nothing (reading 11), so no printed code resolves, and clause [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) fails with it, since it asks whether [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation)'s mechanism resolves a bundled identifier offline and none does, whatever documentation sits on disk (reading 14). A project's own sniff owes only its code printed unaltered, which `-s` gives. Clause [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fails for the same reason, and would fail even for a lookup keyed on the full code: 151 of the 204 bundled sniffs have a documentation file, and for one without, such as `Squiz.Functions.MultiLineFunctionDeclaration`, the generator prints nothing and exits 0, which is the dangling case the clause guards against. Clause [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) fails because a note after `--` on an ignore comment is optional rather than required ([advanced usage](https://github.com/PHPCSStandards/PHP_CodeSniffer/wiki/Advanced-Usage)). Clause [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is not met, since `addError` requires a code but nothing checks that it is stable, and clause [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) fails under reading 28: of the 53 bundled sniffs with no documentation file, 33, such as `Squiz.PHP.Eval` and `Squiz.Functions.MultiLineFunctionDeclaration`, are named on no page of the project's [wiki](https://github.com/PHPCSStandards/PHP_CodeSniffer/wiki) either, so the release shipped codes whose documentation resolves nowhere (counted at 4.0.4 against the wiki cloned on 2026-10-11).

## Notes for a practitioner

Put `<arg value="s"/>` in the ruleset so every finding carries its code, never rename a sniff once its code has been printed, and prove a new sniff with `phpcs --sniffs=... fixture.php`. To read a bundled sniff's documentation offline, drop the last segment of the printed code and pass the rest to `phpcs --generator=Text --sniffs=`, and treat empty output as no documentation. Set `--ignore-annotations` in the ruleset or ban `phpcs:ignore` with a sniff of your own, and keep exclusions as ruleset `<exclude-pattern>` entries with a comment above each.
