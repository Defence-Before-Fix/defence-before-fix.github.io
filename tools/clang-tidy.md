# clang-tidy

{% include tool-grades.html %}

clang-tidy is the LLVM project's linter for C, C++ and Objective-C, built on the Clang front end, with several hundred checks in modules such as `bugprone`, `cert`, `modernize` and `readability`, and the Clang Static Analyzer's path-sensitive checks as `clang-analyzer-*`. In a pipeline it is the main semantic check beside the compiler's own warnings, and it is the strongest host for a project's own C or C++ rules, by configuration or by a compiled module.

## How it is conformant

A project can add a rule two ways, and [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) rests on the second, the compiled module, since the first is experimental. Since LLVM 22 a `.clang-tidy` file may declare `CustomChecks`, each a `clang-query` matcher with a `Name` and a diagnostic message, enabled with `--experimental-custom-checks` ([query based custom checks](https://github.com/llvm/llvm-project/blob/llvmorg-23.1.3/clang-tools-extra/docs/clang-tidy/QueryBasedCustomChecks.rst)); a probe check `no-strcpy` reported `a.c:6:5: warning: use a bounded copy [custom-no-strcpy]` at version 23.1.3. And `--load=<pluginfilename>` loads a compiled module of `ClangTidyCheck` classes ([clang-tidy](https://github.com/llvm/llvm-project/blob/llvmorg-23.1.3/clang-tools-extra/docs/clang-tidy/index.rst), in-tree example [CTTestTidyModule.cpp](https://github.com/llvm/llvm-project/blob/llvmorg-23.1.3/clang-tools-extra/test/clang-tidy/CTTestTidyModule.cpp)); a probe module built against the release's headers registered `proj-no-nolint` and ran. `--checks='-*,<name>'` runs one check, bundled or custom, against one file, as `clang-tidy a.c -- -std=c11` with no compilation database, and printed only that check's findings ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file)). The identifier is printed in brackets after every finding and as `DiagnosticName` in the `--export-fixes` YAML, the only other output, and a module check prints the name its author registers, `[proj-no-nolint]`, ran ([4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding)). Under `--warnings-as-errors`, which a defence needs to fail the run, the bracket printed `[proj-no-nolint,-warnings-as-errors]` (ran, for a module check and a query check alike); the comma separates list entries, so the name is printed whole beside a separately delimited token, which the register does not count as an alteration, as on [Android Lint](android-lint.md). The grade rests on the module route, the one [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) rests on; the query route alters the name, below. Bundled names such as `bugprone-use-after-move` are assigned by the maintainers. clang-tidy runs locally, prints its findings in the command's own output, and has no hosted or paid tier ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran), [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)).

clang-tidy offers `NOLINT`, `NOLINTNEXTLINE` and `NOLINTBEGIN`/`NOLINTEND` comments, optionally naming checks, and no option to ignore them ([suppressing undesired diagnostics](https://github.com/llvm/llvm-project/blob/llvmorg-23.1.3/clang-tools-extra/docs/clang-tidy/index.rst)). The route is detectable by a rule the project writes in the detector itself: a check can register a comment handler in `registerPPCallbacks`, as the bundled `google-readability-todo` does ([TodoCommentCheck.cpp](https://github.com/llvm/llvm-project/blob/llvmorg-23.1.3/clang-tools-extra/clang-tidy/google/TodoCommentCheck.cpp)), and the probe module did so, reporting all four `NOLINT` forms in a fixture and failing the run with `--warnings-as-errors='proj-*'` (exit 1) ([7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable)). Each run also prints a count such as `Suppressed 1 warnings (1 NOLINT).` unless `--quiet` is set.

## How it is not conformant

The experimental query route does not meet [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding): a query check's `Name: no-strcpy` printed as `custom-no-strcpy`, a prefix the tool joins to the name, documented and fixed, but not the name the author wrote ([query based custom checks](https://github.com/llvm/llvm-project/blob/llvmorg-23.1.3/clang-tools-extra/docs/clang-tidy/QueryBasedCustomChecks.rst)).

Nothing resolves a bundled check's name as printed, online or offline; a project check's name is printed unaltered, the half [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) asks of a project's own rule, so the row is decided by the bundled checks. The documentation is one page per check on clang.llvm.org ([list of checks](https://clang.llvm.org/extra/clang-tidy/checks/list.html)), at an address built by splitting the name into a module directory and a file (`checks/bugprone/use-after-move.html` for `bugprone-use-after-move`, `checks/clang-analyzer/core.DivideZero.html` for `clang-analyzer-core.DivideZero`); the name as printed, `checks/bugprone-use-after-move.html`, returned 404, fetched. The list of checks links each name to that address and carries no anchor keyed on the name. An address keyed on a transformation of the identifier is the index [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) rules out ("An index keyed on anything else does not resolve it"), and no command resolves the name either: `--list-checks` lists names only, `--explain-config` says where each check was enabled, and neither the LLVM 23.1.3 release archive nor the PyPI `clang-tidy` wheel installs the documentation ([6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together)). Compiler diagnostics reported as `clang-diagnostic-*` resolve only in Clang's own online reference. A query check's syntax "may be changed in the future" whilst it is experimental, and a query matches syntax tree nodes, not comments, so the `NOLINT` detector above needs a compiled module built against the matching LLVM headers. That detector had to report without a source location: reported at the comment, a bare `// NOLINT` silenced the very finding about it; reported without one, it was not silenced even by `// NOLINT(proj-no-nolint)` or a `NOLINTBEGIN(proj-no-nolint)` block, which name it, ran. A `NOLINT` may carry a reason after a colon, but nothing requires one ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)). There is no rule over the rules ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)); `--verify-config` reported the configured `custom-no-strcpy` as an unknown check. No release gate over the documentation was found ([6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation), not verified).

Readiness is 🟢: a bespoke module check, a single-check run and a printed name all hold. The detector grade is 🟡 because of [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together). clang-tidy declares no version of this document.

## Notes for a practitioner

Write a simple class as a query check in `.clang-tidy` and a harder one, or anything that needs comments or the preprocessor, as a module loaded with `--load`, built against the exact LLVM version the project pins. Prove it with `--checks='-*,<name>'` on a fixture file. Forbid or audit `NOLINT` with a module check that reports without a source location, run with `--warnings-as-errors`, read the name as the first comma-separated entry in the bracket, before `,-warnings-as-errors`, and keep a local copy of the check documentation the project relies on, since clang-tidy will not resolve a name offline.
