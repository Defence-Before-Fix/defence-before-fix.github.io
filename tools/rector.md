# Rector

{% include tool-grades.html %}

Rector is an automated refactoring tool built on the PHP parser and PHPStan's type inference. Its job in a pipeline is to rewrite code, but in `--dry-run` mode it is a detector that reports every place a rule would change, and a custom rule can express any pattern the AST exposes, so it can host a bespoke defence whose fix is mechanical.

## How it is conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) is met: a project extends `AbstractRector`, declares the node types and the refactoring, and registers the class with `withRules()` in `rector.php` ([custom rule](https://getrector.com/documentation/custom-rule)). Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is met twice over: `AbstractRectorTestCase` runs a rule over a `.php.inc` fixture with a before and after section ([custom rule](https://getrector.com/documentation/custom-rule)), and `--only="Fully\Qualified\Rule"` runs one registered rule from the command line ([run single rule](https://getrector.com/documentation/run-single-rule)); a flag that selects one rule is Yes under reading 4, and it does select rather than filter: `ConfigurationRuleFilter::filterOnlyRules()` keeps only the named rule among the node traverser's visitors, so no other rule runs (reading 21; [`ConfigurationRuleFilter.php` at 2.7.0](https://github.com/rectorphp/rector-src/blob/2.7.0/src/Configuration/ConfigurationRuleFilter.php)); `process --dry-run --only='Rector\Php54\Rector\Array_\LongArrayToShortArrayRector' src/a.php` reported the one file and exited 2 (ran at 2.7.0). Clauses [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) to [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally) hold: the tool runs locally, accepts a path, and prints the diff and rule name to the terminal. Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is met, and this is unusual: Rector offers no inline route and no baseline. The inline `@noRector` annotation was removed in Rector 0.15 precisely because it hid context ([pull request 3148](https://github.com/rectorphp/rector-src/pull/3148)), and the string appears nowhere in the installed 2.7.0 package (searched); the only skip is `withSkip()` in `rector.php`, the configuration that also chooses the rules, which turns a rule off, or off for the paths it names, and so under reading 29 is configuration, not a route (it is not an inline comment, a directive or a file of entries naming findings) ([ignoring rules or paths](https://getrector.com/documentation/ignoring-rules-or-paths)). Its use can be seen: `validate-config`, and every `process` run, warn of a skipped rule that is never registered (ran at 2.7.0).

## How it is not conformant

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails, and since a No on it is structural under reading 1, it decides the grade: the string printed with a finding is the rule's class name, which the clause forbids as an identifier because a rename or a namespace move changes it, and there is no field for the author to choose one, so under reading 5 no rule can carry any other identifier. The form even differs between outputs: `process --dry-run` printed the short name, `LongArrayToShortArrayRector`, as did the `github` and `gitlab` formats, both deprecated at 2.7.0, and `--output-format=json` printed the fully qualified one under `applied_rectors`, `Rector\Php54\Rector\Array_\LongArrayToShortArrayRector` (all ran at 2.7.0). Clause [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) fails for the bundled rules, which decide the row under reading 13: Rector prints no documentation address with a finding, installs no documentation, and ships no command that takes a rule's name, `list-rules` now answering that it is "deprecated and no longer provided" (ran at 2.7.0), so under reading 10 it provides no mechanism. Each bundled rule's class does carry a description and a code sample in its `getRuleDefinition()`, but under reading 12 a rule's source is not documentation unless a mechanism of Rector's own presents it, and none does. The website files each rule at a re-spelt address, `https://getrector.com/rule-detail/long-array-to-short-array-rector`, and `rule-detail/LongArrayToShortArrayRector`, the name as the console prints it, redirects there (fetched on the checked date), but Rector neither prints that address nor states its form as the way to look a rule up, so under reading 10 it is not a mechanism Rector provides, and it is online. Clauses [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) then fail, since with no mechanism no bundled name resolves offline (reading 14). Clause [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) has no route to apply to, so it is not applicable; `withSkip()`, which takes classes and paths with no field for a reason ([ignoring rules or paths](https://getrector.com/documentation/ignoring-rules-or-paths)), is configuration under reading 29, and a comment beside each entry is the project's own practice. Clause [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is not met and clause [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) was not verified.

## Notes for a practitioner

Rector suits a defence whose remedy is a transformation you can state exactly: write the rule, prove it with a fixture under `AbstractRectorTestCase`, sweep with `--dry-run`, and enforce with `--dry-run` failing the build. Treat the class name as the identifier and never move it, and put a comment beside every `withSkip()` entry because the configuration will not ask for one. Run `validate-config` in the gate, which fails on a skipped rule that is no longer registered.
