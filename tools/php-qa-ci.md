# php-qa-ci

{% include tool-grades.html %}

php-qa-ci is a Composer plugin that wraps PHPStan, PHPArkitect, PHPUnit, PHP CS Fixer, Rector, Infection and a set of its own lanes behind one `bin/qa` entry point, ships a bundle of PHPStan rules with their documentation, and writes an agent-facing block into the consuming project. It is the PHP reference toolchain for this method, and this page grades it with the same scrutiny as every other entry ([repository](https://github.com/LongTermSupport/php-qa-ci)).

Every mechanism below was checked by running it in a checkout: `bin/qa`, `bin/qa -t <tool> -p <path>`, `bin/rules`, `bin/rule-doc <identifier>` and `bin/phpstan-rule <identifier> <path>`. Detector conformance is graded on the detectors the toolchain routes defences through, each together with the wrapping around it, as toolchain clause [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification) requires. Toolchain conformance grades the artefact a consuming project installs. Project conformance grades the repository as a project following the method with the toolchain it ships.

## How it is conformant

For its own PHPStan bundle, every detector clause holds. A project's rules go under `rules:` in its `qaConfig/phpstan.neon` (detector [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)). `bin/phpstan-rule phpqaci.nullCoalescingFalse src/ZzProbe.php` on a probe containing `?? false` printed `FIRED (1)` with the location and exited 1, and the same command for `phpqaci.nestedTernary` printed `did not fire` (detector [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)). PHPStan prints the `phpqaci.*` identifier under every finding, and `RequireRuleIdentifierConstantRule`, on by default, rejects a magic-string identifier (detector [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), detector [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)). `bin/qa -t phpstan -p <file>` runs one lane over one file locally with the result in the terminal, and the CI script runs the same `bin/qa` (detector [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) to detector [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)). `bin/rule-doc phpqaci.nestedTernary` resolves the identifier as printed to its rule, bundle, source and shipped page, offline, and the page carries a `The correct construction` section (detector [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) to detector [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) for the bundle). `RuleDocumentationTest` fails the build when a declared identifier resolves to no page, or to a page whose construction section is missing or only restates the summary (detector [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation)). Inline `@phpstan-ignore` in every form is a finding of `ForbidInlinePhpstanIgnoreRule` (detector [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable)), and behind it the default tier turns on PHPStan's `reportIgnoresWithoutComments`: a probe ignore with no reason printed both `phpqaci.inlinePhpstanIgnore` and `ignore.noComment (non-ignorable)` (detector [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)).

At toolchain level, every lane prints a stable identifier when it fails: a run of `bin/qa -t branchNamePolicy` on a `plan/*` branch ended with `🪪 phpqaci.branchNamePolicy (vendor/bin/rule-doc phpqaci.branchNamePolicy)`, and `EveryLaneNamesItselfTest` fails the build on a lane without one. `bin/rule-doc phpqaci.packageType` resolves a lane identifier to its page as it does a rule's, and `bin/rules .` prints no `no documentation page` row: all 69 indexed identifiers (`bin/rule-doc --list`) resolve to a page ([4.2](../TOOLING-SPEC.md#42-the-toolchain-must-resolve-every-identifier-a-defence-it-routes-can-print-from-the-installed-copy-without-network-access)). `bin/rules .` lists every rule in the resolved neon chain, including the rules `phpstan/extension-installer` delivers, with the package each came from, and every lane with its identifier and documentation route; phase runners alone carry none ([5.1](../TOOLING-SPEC.md#51-the-toolchain-must-be-able-to-list-the-defences-active-in-a-project-without-triggering-them) to [5.3](../TOOLING-SPEC.md#53-a-projects-own-defences-must-appear-in-the-listing-alongside-bundled-ones)). The record is the `ignoreErrors` block PHPStan itself loads ([6.1](../TOOLING-SPEC.md#61-the-toolchain-must-define-a-location-for-the-project-record-and-must-read-it-itself)); the `pij` lane reads it through every `includes:` file, and a probe baseline included from `qaConfig/phpstan.neon` with an uncommented entry failed it, naming the included file and line ([6.2](../TOOLING-SPEC.md#62-every-exception-in-the-project-record-must-carry-a-written-justification-that-names-the-hazard-and-the-scope-and-the-toolchain-must-reject-a-generic-one), [4.3](../TOOLING-SPEC.md#43-the-toolchain-must-forbid-through-a-defence-of-its-own-every-suppression-route-that-bypasses-the-project-record)). A `phparkitect-baseline.json` is never read: on a probe project with one violation, PHPArkitect with a generated baseline printed `No violations detected`, and with `--skip-baseline`, which the lane always passes, reported the violation; the lane names the file when one is present ([4.3](../TOOLING-SPEC.md#43-the-toolchain-must-forbid-through-a-defence-of-its-own-every-suppression-route-that-bypasses-the-project-record)). The same listing enumerates the record beside the defences, together with the deferred-defect and no-pattern record `qaConfig/defect-record.neon` (`defectRecord` in `--json`), which the same lane fails on when an entry does not read in full ([6.3](../TOOLING-SPEC.md#63-the-project-record-must-be-enumerable-by-the-same-means-as-the-defences)). `docs/defence-before-fix-defaults.md` states the toolchain's default for the owner, the project record, the sweep scope, fixtures and the method's three calibrations, linked from the agent block ([6.4](../TOOLING-SPEC.md#64-the-toolchain-should-state-its-own-defaults-for-anything-the-method-leaves-to-the-project)). The entry point runs coding standards, linting and static analysis before tests and stops on a failure ([4.5](../TOOLING-SPEC.md#45-the-toolchains-entry-point-must-run-detectors-before-runners-and-must-stop-on-a-detector-failure)). `bin/rules --write-agent-summary` writes one line per active defence, identifier and page, into a marked region of the project's `CLAUDE.md`, refreshed on every install and update ([7.1](../TOOLING-SPEC.md#71-the-toolchain-should-generate-a-summary-of-the-active-defences-suitable-for-an-agents-context), [7.2](../TOOLING-SPEC.md#72-the-toolchain-should-deliver-that-summary-into-the-project-automatically)). The release guard covers rules and lanes and requires a page stating a correct construction ([8.1](../TOOLING-SPEC.md#81-a-shipped-toolchain-must-fail-its-own-release-if-a-bundled-defence-lacks-resolvable-documentation)), and the self-check runs both bundled rule sets and the PHPArkitect tier on the package's own source ([8.2](../TOOLING-SPEC.md#82-a-shipped-toolchain-must-run-its-own-bundled-defences-on-its-own-source)). The manifest declares method 1.1.0 and toolchain 0.2.0 at both levels, with the gaps below recorded against their clauses, and `DefenceBeforeFixDeclarationTest` holds each recorded gap to a decision and a probe that fails when the gap closes ([9.2](../TOOLING-SPEC.md#92-the-declaration-is-the-claim-and-the-known-gap-record-not-a-condition-of-conformance)).

## How it is not conformant

Toolchain clause [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification) still fails, two ways, both declared in `known-gaps` as accepted by the owner. PHPArkitect, through which the on-by-default rule tier routes bundled defences, prints a violation as prose with no identifier per rule, so as wrapped it fails detector [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), detector [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file) and detector [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) to detector [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) for the rules of its tier; the lane itself prints `phpqaci.phpArkitect` and resolves to a page. And PHPStan's native identifiers resolve online only: `bin/rule-doc method.notFound` names the phpstan.org page and says the catalogue is not carried offline, so the wrapping does not close detector [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and detector [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) for the detector's own catalogue.

Project conformance carries the same gap, because the repository runs the toolchain it ships. Its own record is one justified entry, enumerable in the listing, and its contributor-only rules are listed and run.

## Tools it bundles

php-qa-ci is a toolchain rather than a tool, so the question for each lane it runs is whether that lane can host a bespoke defence under the method, and which of the toolchain's own mechanisms wrap it. Every lane below is registered by `bin/qa`, appears in the `bin/rules` listing with its identifier and page, prints that identifier on failure, and resolves through `bin/rule-doc`.

- **PHPStan**: hosts bespoke defences; wrapped by `bin/phpstan-rule`, `bin/rule-doc` and `bin/rules`, with the bundled rules and the identifier constant enforced on top. Conforms as wrapped for the `phpqaci.*` bundle; fails detector [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and detector [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) for its native catalogue.
- **PHPArkitect**: hosts bespoke defences about architecture through `phparkitect.php`; the lane prints `phpqaci.phpArkitect` and never reads a baseline, but the rules of its tier carry no identifier, single-file run or resolver. Does not conform as wrapped, and the default tier routes bundled defences through it.
- **Rector and PHP CS Fixer**: a refactoring tool and a formatter, run as checks; neither hosts a defence in the method's sense.
- **PSR-4 validation, Composer validation, composer require checker, composer dependency analyser, PHP lint, Markdown links, YAML lint, ShellCheck**: fixed checks; not hosts.
- **Package type, config template ignore-list audit, Infection config source dirs, version pins, changelog, strict types, OPcache, documentation prose, branch name policy, SensitiveParameter usage**: bundled defences of the toolchain's own, each a lane with its identifier and page.
- **PHPStan ignoreErrors justification**: the toolchain clause [6.2](../TOOLING-SPEC.md#62-every-exception-in-the-project-record-must-carry-a-written-justification-that-names-the-hazard-and-the-scope-and-the-toolchain-must-reject-a-generic-one) mechanism, a bundled defence over the project record, reading the whole include chain.
- **PHPUnit and Infection**: a test runner and a mutation tester; neither can host a defence, since the method rules out a test as the net.
- **Dead code and copy/paste detection**: an opt-in PHPStan extension lane and an informational report; not hosts.

## Notes for a practitioner

Install the plugin, write the rule under `rules:` with a `phpqaci`-style identifier constant, prove it with `bin/phpstan-rule` on a fixture, sweep with `bin/qa -t phpstan`, and add the documentation page with a construction section so `bin/rule-doc` resolves it and the release guard accepts it. Run `bin/rules .` first on any project you arrive at, or read the active-defences region of its `CLAUDE.md`: the listing and the justified exceptions are the record the method tells you to read before guessing, and where the project has recorded nothing, `docs/defence-before-fix-defaults.md` is the default it falls back to. Treat a PHPArkitect violation as a defence whose rule has no identifier of its own.
