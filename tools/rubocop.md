# RuboCop

{% include tool-grades.html %}

RuboCop is the standard linter and formatter for Ruby: a set of cops, grouped into departments such as `Lint` and `Style`, that walk the parser's syntax tree and report offences under names such as `Lint/UselessAssignment`. In a pipeline it is usually the first and often the only Ruby check, run on every edit, and it is also the language's host for bespoke rules, since a project's own cop is a Ruby class loaded beside the bundled ones.

## How it is conformant

A project writes a cop as a subclass of `RuboCop::Cop::Base` and loads it with `require:` (or `plugins:` for a gem) in `.rubocop.yml`, where it is configured "just like any other cop" ([plugins](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/plugins.adoc), [development](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/development.adoc)); a probe cop `Proj/NoSleep` loaded this way reported `s.rb:3:1: C: Proj/NoSleep: PROJ: do not call sleep.` at version 1.92.0 ([4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)). The gem ships `RuboCop::RSpec::ExpectOffense` ([source](https://github.com/rubocop/rubocop/blob/v1.92.0/lib/rubocop/rspec/expect_offense.rb)), whose `expect_offense` and `expect_no_offenses` run one cop against a fixture string; a two-example spec for the probe cop passed under RSpec, and `rubocop --only Proj/NoSleep s.rb` ran that one cop from the command line with every other cop silent; the harness and the flag are each Yes under reading 4 ([CLI reference](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/usage/cli_reference.adoc)) ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)). RuboCop runs locally on a single file with no service and no licence tier, and by default prints every offence with its cop name in the command's own output ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file), [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)). The cop name was printed unaltered in the default `progress` output and in the `simple`, `clang`, `emacs`, `json`, `junit`, `sarif` (as `ruleId`), `github`, `tap`, `markdown`, `html`, `pacman` and `quiet` formats, ran at 1.92.0; the `offenses`, `worst`, `files` and `autogenconf` formats print no individual offence.

`rubocop --show-cops Lint/UselessAssignment`, a command RuboCop ships (reading 10), takes the name exactly as printed (reading 11) and prints the cop's `Description` and configuration from the installed gem's `config/default.yml`, and `rubocop --explain Lint/UselessAssignment`, added in 1.92.0, prints the description, properties, configuration and the examples from the cop's own documentation; both ran with the network removed (`unshare -rn`), and both exit 2 on a name they do not know, with `Unrecognized cop: Lint/NoSuchCop.` ([6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access)). `--show-docs-url` prints an online address keyed on the department and the lower-cased name, `cops_lint.html#lintuselessassignment`, which by itself would resolve nothing (reading 11); the offline commands are what decide the clauses. The description ships in the same gem as the cop, and a script over the cop registry at version 1.92.0 found a `Description` for all 613 bundled cops, and `--explain` given all 613 names, offline, printed an entry for each, ran (reading 14) ([6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together)). `--show-cops` prints the `Description` a project sets for its own cop, and `--explain Proj/NoSleep` printed the probe cop's class comment as its details, which goes further than [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) asks. The repository's test suite fails when any cop lacks a `Description` ([project spec](https://github.com/rubocop/rubocop/blob/v1.92.0/spec/project_spec.rb)), which is an automated check over every bundled name ([6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation), partial: it is a test, not a step of the release task).

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) holds three ways for the inline directives (`rubocop:disable`, `todo`, `disable-next`, `push` and the rest, [source code directives](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/usage/source_code_directives.adoc)), each ran at 1.92.0. `--ignore-disable-comments` reports offences "even if they have been manually disabled", a documented flag under which the route is not applied (reading 17). `--display-suppressed`, new in 1.92.0, lists every offence a directive suppressed, tagged `[Suppressed]` in text and `"suppressed": true` in JSON, without changing the exit code, so the route is detectable by the detector itself (reading 18). And the bundled `Style/DisableCopsWithinSourceCodeDirective`, off by default, reports every directive, including `# rubocop:disable all`, and once enabled "no directive can disable it at all": a `# rubocop:disable Style/DisableCopsWithinSourceCodeDirective` was itself reported, which is the documented way reading 19 asks for. The generated `.rubocop_todo.yml` baseline applies only where the configuration includes it. With `AllowWithReason: true` the same cop accepts only a directive carrying a `-- reason` and reported each one without it, which is the shape [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) asks for, off by default.

## How it is not conformant

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails. A cop's name is not chosen in a field of its own: `Base.badge` is `Badge.for(name)`, built from the Ruby module and class name ([source](https://github.com/rubocop/rubocop/blob/v1.92.0/lib/rubocop/cop/badge.rb)), so `RuboCop::Cop::Proj::NoSleep` prints `Proj/NoSleep`, and renaming the class or its module renames the identifier, which is the class-derived form the clause names as not stable. For bundled cops RuboCop softens this in practice: its [versioning policy](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/versioning.adoc) makes "renaming or moving cops (with backwards-compatible obsoletions)" a minor-release event, and `config/obsoletion.yml` maps old names to new ones, but the rename still changes the printed name. `--no-display-cop-names` and `DisplayCopNames: false` remove the name from text output, ran, so a project should leave them at their default. Clause [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) is partial under reading 8: `-o <file>` given alone moved every offence and the summary line into the file, and the console carried neither a count nor the file's location, ran at 1.92.0; giving a second `-f` with no `-o` after it keeps a report on the console as well ([CLI reference](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/usage/cli_reference.adoc)). There is no rule over the rules ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)). The generated `.rubocop_todo.yml` records an offence count, not a reason, for each entry ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason), in part). Readiness is 🟡 rather than 🟢 because the printed name, though always present, is derived from the class; the workaround is to choose the class and module name as carefully as an identifier and never rename them. The detector grade is 🔴 because [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails, and it is structural (reading 1): no cop, bundled or project, can carry an identifier other than one built from its class, which reading 5 grades No, as it does Rector's. RuboCop declares no version of this document.

## Notes for a practitioner

Write the class as a cop in a department named for the project, choose its class name as carefully as an identifier, because it is one, and never rename it once a finding has been reported under it. Prove it with `expect_offense` and then with `rubocop --only <Department/Name>` on the originating file. Enable `Style/DisableCopsWithinSourceCodeDirective` with `AllowWithReason: true`, keep `Lint/RedundantCopDisableDirective` on, and run `--display-suppressed` or `--ignore-disable-comments` in the project's audit so that every suppression is both reasoned and visible; treat `.rubocop_todo.yml` as a dated record to shrink, not a place to add to.
