# RuboCop

{% include tool-grades.html %}

RuboCop is the standard linter and formatter for Ruby: a set of cops, grouped into departments such as `Lint` and `Style`, that walk the parser's syntax tree and report offences under names such as `Lint/UselessAssignment`. In a pipeline it is usually the first and often the only Ruby check, run on every edit, and it is also the language's host for bespoke rules, since a project's own cop is a Ruby class loaded beside the bundled ones.

## How it is conformant

A project writes a cop as a subclass of `RuboCop::Cop::Base` and loads it with `require:` (or `plugins:` for a gem) in `.rubocop.yml`, where it is configured "just like any other cop" ([plugins](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/plugins.adoc), [development](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/development.adoc)); a probe cop `Proj/NoSleep` loaded this way reported `s.rb:3:1: C: Proj/NoSleep: PROJ: do not call sleep.` at version 1.92.0 ([4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)). The gem ships `RuboCop::RSpec::ExpectOffense` ([source](https://github.com/rubocop/rubocop/blob/v1.92.0/lib/rubocop/rspec/expect_offense.rb)), whose `expect_offense` and `expect_no_offenses` run one cop against a fixture string; a two-example spec for the probe cop passed under RSpec, and `rubocop --only Proj/NoSleep s.rb` ran that one cop from the command line with every other cop silent, and it runs only that cop rather than filtering the output, since the runner selects the cops to load by the names given before the run (`mobilized_cop_classes` in [`runner.rb`](https://github.com/rubocop/rubocop/blob/v1.92.0/lib/rubocop/runner.rb); reading 21); the harness and the flag are each Yes under reading 4 ([CLI reference](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/usage/cli_reference.adoc)) ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)). RuboCop runs locally on a single file with no service and no licence tier, and by default prints every offence with its cop name in the command's own output ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file), [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)). The cop name was printed unaltered in the default `progress` output and in the `simple`, `clang`, `emacs`, `json`, `junit`, `sarif` (as `ruleId`), `github`, `tap`, `markdown`, `html`, `pacman` and `quiet` formats, ran at 1.92.0; the `offenses`, `worst`, `files` and `autogenconf` formats print no individual offence.

`rubocop --show-cops Lint/UselessAssignment`, a command RuboCop ships (reading 10), takes the name exactly as printed (reading 11) and prints the cop's `Description` and configuration from the installed gem's `config/default.yml`, and `rubocop --explain Lint/UselessAssignment`, added in 1.92.0, prints the description, properties, configuration and the examples from the cop's own documentation; both ran with the network removed (`unshare -rn`), and both exit 2 on a name they do not know, with `Unrecognized cop: Lint/NoSuchCop.` ([6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access)). `--show-docs-url` prints an online address keyed on the department and the lower-cased name, `cops_lint.html#lintuselessassignment`, which by itself would resolve nothing (reading 11); the offline commands are what decide the clauses. The description ships in the same gem as the cop, and a script over the cop registry at version 1.92.0 found a `Description` for all 613 bundled cops, and `--explain` given all 613 names, offline, printed an entry for each, ran (reading 14); that includes `Lint/Syntax`, the name RuboCop prints for a file it cannot parse (`def f(` gave `Lint/Syntax: unexpected token $end`), which `--explain Lint/Syntax` resolved offline, ran (reading 27) ([6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together)). `--show-cops` prints the `Description` a project sets for its own cop, and `--explain Proj/NoSleep` printed the probe cop's class comment as its details, which goes further than [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) asks. The repository's test suite fails when any cop lacks a `Description` ([project spec](https://github.com/rubocop/rubocop/blob/v1.92.0/spec/project_spec.rb)), but the release does not wait on it, so [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is No under reading 28, with every bundled name landing on a page: at the tag, `tasks/cut_release.rake` depends only on `references:verify`, which fetches the `References` URLs in `config/default.yml`, and `changelog:check_clean`, then regenerates the cop documentation, whose generator (`lib/rubocop/cops_documentation_generator.rb`) writes "No documentation" for a cop without one rather than failing; `rake release` waits only on the clean changelog, and `.github/workflows/github_release.yml` publishes the notes for a pushed tag and runs nothing else.

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) holds three ways for the inline directives (`rubocop:disable`, `todo`, `disable-next`, `push` and the rest, [source code directives](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/usage/source_code_directives.adoc)), each ran at 1.92.0. `--ignore-disable-comments` reports offences "even if they have been manually disabled", a documented flag under which the route is not applied (reading 17). `--display-suppressed`, new in 1.92.0, lists every offence a directive suppressed, tagged `[Suppressed]` in text and `"suppressed": true` in JSON, without changing the exit code, so the route is detectable by the detector itself (reading 18). And the bundled `Style/DisableCopsWithinSourceCodeDirective`, off by default, reports every directive, including `# rubocop:disable all`, and once enabled "no directive can disable it at all": a `# rubocop:disable Style/DisableCopsWithinSourceCodeDirective` was itself reported, which is the documented way reading 19 asks for. The generated `.rubocop_todo.yml` turns cops off for the files listed under each, or raises their limits, which is configuration rather than a route (reading 29), and it applies only where the configuration includes it. With `AllowWithReason: true` the same cop accepts only a directive carrying a `-- reason` and reported each one without it, which is the shape [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) asks for, off by default. The directives are the only route reading 30 asks it of: the todo file is configuration, and RuboCop honours no generated-code header or other skip marker (no such marker in `lib/` at the tag; reading 29), so the one route can be configured to reject a directive without a reason, and [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) is Yes.

## How it is not conformant

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails. A cop's name is not chosen in a field of its own: `Base.badge` is `Badge.for(name)`, built from the Ruby module and class name ([source](https://github.com/rubocop/rubocop/blob/v1.92.0/lib/rubocop/cop/badge.rb)), so `RuboCop::Cop::Proj::NoSleep` prints `Proj/NoSleep`, and renaming the class or its module renames the identifier, which is the class-derived form the clause names as not stable. For bundled cops RuboCop softens this in practice: its [versioning policy](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/versioning.adoc) makes "renaming or moving cops (with backwards-compatible obsoletions)" a minor-release event, and `config/obsoletion.yml` maps old names to new ones, but the rename still changes the printed name. `--no-display-cop-names` and `DisplayCopNames: false` remove the name from text output, ran, so a project should leave them at their default. Clause [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) is partial under reading 8: `-o <file>` given alone moved every offence and the summary line into the file, and the console carried neither a count nor the file's location, ran at 1.92.0; giving a second `-f` with no `-o` after it keeps a report on the console as well ([CLI reference](https://github.com/rubocop/rubocop/blob/v1.92.0/docs/modules/ROOT/pages/usage/cli_reference.adoc)). There is no rule over the rules, and that every cop has a name is no enforcement by construction, since the name it is given is the class-derived one [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own), No, reading 7). The generated `.rubocop_todo.yml` records an offence count, not a reason, for each entry, and as configuration it hides those offences without a sign (reading 29). Clause [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is No, since no step of the release checks the documentation (above). Readiness is 🟡 rather than 🟢 because the printed name, though always present, is derived from the class; the workarounds are to choose the class and module name as carefully as an identifier and never rename them, and to write an identifier at the start of the cop's message, which RuboCop prints whole (`Proj/NoSleep: PROJ: do not call sleep.` above), which moves readiness and does not meet the clause (readings 2 and 20). The detector grade is 🔴 because [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails, and it is structural (reading 1): no cop, bundled or project, can carry an identifier other than one built from its class, which reading 5 grades No, as it does Rector's. RuboCop declares no version of this document.

## Notes for a practitioner

Write the class as a cop in a department named for the project, choose its class name as carefully as an identifier, because it is one, and never rename it once a finding has been reported under it. Prove it with `expect_offense` and then with `rubocop --only <Department/Name>` on the originating file. Enable `Style/DisableCopsWithinSourceCodeDirective` with `AllowWithReason: true`, keep `Lint/RedundantCopDisableDirective` on, and run `--display-suppressed` or `--ignore-disable-comments` in the project's audit so that every suppression is both reasoned and visible; treat `.rubocop_todo.yml` as a dated record to shrink, not a place to add to.
