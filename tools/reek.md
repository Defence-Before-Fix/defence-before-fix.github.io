# Reek

{% include tool-grades.html %}

Reek is a code smell detector for Ruby: 29 detectors, such as `UtilityFunction`, `FeatureEnvy` and `TooManyStatements`, that walk the parser's syntax tree and report design smells in modules and methods rather than style. In a pipeline it runs beside RuboCop as a second, design-level check, usually through its command or its Rake task, with a `.reek.yml` tuning or excluding detectors per context.

## How it is conformant

`reek --smell UtilityFunction r.rb` runs one detector against one file and printed only its finding, `[3]:UtilityFunction: Foo#bar doesn't depend on instance state`, exit 2 ([command-line options](https://github.com/troessner/reek/blob/v6.6.0/docs/Command-Line-Options.md), ran), running only that detector, since the examiner builds its detector list from the types given before the run (`eligible_smell_types` in [`detector_repository.rb`](https://github.com/troessner/reek/blob/v6.6.0/lib/reek/detector_repository.rb); reading 21), and the gem's RSpec matcher `reek_of` tests code for one smell type ([RSpec matchers](https://github.com/troessner/reek/blob/v6.6.0/docs/RSpec-matchers.md)) ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code), graded on the bundled detectors). Reek runs locally on a single file, or on standard input, with no service and no licence tier, and prints every finding in the command's own output; it has no option that writes the report elsewhere ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) to [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally), ran).

## How it is not conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) fails. Reek offers no way to load a project's own detector: `reek --help` has no load or require option, and the [guide to writing detectors](https://github.com/troessner/reek/blob/v6.6.0/docs/How-To-Write-New-Detectors.md) is for contributors, placing every detector in `lib/reek/smell_detectors` and asking for the idea to be discussed in an issue first. Detectors register by subclassing the internal `BaseDetector`, whose subclasses the [detector repository](https://github.com/troessner/reek/blob/v6.6.0/lib/reek/detector_repository.rb) collects. A subclass preloaded into the interpreter with `RUBYOPT=-r<file>` did run and print its finding (ran), but that is Ruby loading a file before Reek starts, against a class Reek does not document for this use, not a mechanism Reek supports.

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails. A detector's smell type, the identifier printed with each finding, is `name.split('::').last`, the detector's class name ([`base_detector.rb`](https://github.com/troessner/reek/blob/v6.6.0/lib/reek/smell_detectors/base_detector.rb)), which is the derivation [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) rules out (reading 5), and with no project detectors there is no rule that carries any other. The smell type is printed unaltered in every format: text, single-line text, YAML and JSON (as `smell_type`), XML (as `source`), HTML and GitHub annotations (ran). There is no rule over the rules, and that every detector has a smell type is no enforcement by construction, since the type it is given is the class-derived one [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own), No, reading 7).

Clauses [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) to [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fail, because no mechanism Reek provides resolves a smell type. The default output prints a documentation link beside each finding, such as `https://github.com/troessner/reek/blob/v6.6.0/docs/Utility-Function.md`, which is the smell type re-spelt with hyphens on the project's website ([`documentation_link.rb`](https://github.com/troessner/reek/blob/v6.6.0/lib/reek/documentation_link.rb)); it is keyed on a transformed address and needs the network, so it resolves nothing under reading 11, and the `docs/` pages it names are left out of the gem ([`reek.gemspec`](https://github.com/troessner/reek/blob/v6.6.0/reek.gemspec)). `reek -l` lists the smell types with no description. The installed gem does carry [`lib/reek/code_climate/code_climate_configuration.yml`](https://github.com/troessner/reek/blob/v6.6.0/lib/reek/code_climate/code_climate_configuration.yml), whose entries are labelled with each smell type exactly as printed and hold its explanation as `content`, and a script run with the network removed (`unshare -rn`) found an entry for all 29 smell types; but that file is the data of the Code Climate formatter, which presents the text in its report ([`code_climate_formatter.rb`](https://github.com/troessner/reek/blob/v6.6.0/lib/reek/code_climate/code_climate_formatter.rb)), and a file installed for another purpose, such as a formatter's data, is not a mechanism (reading 26). With no mechanism, no bundled identifier resolves from the installed copy ([6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), reading 14), and none resolves to documentation shipped with it ([6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together)).

Clause [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is not verified. Every one of the 29 smell types has the `docs/` page its printed link names, in the repository at the tag (checked by building each link with Reek's own `DocumentationLink`), so each resolves somewhere and reading 28's No does not apply. The repository's [specification for the formatter's file](https://github.com/troessner/reek/blob/v6.6.0/spec/reek/code_climate/code_climate_configuration_spec.rb) fails when a detector lacks `content`, but that checks the formatter's data, not documentation a mechanism resolves, and the release task from `bundler/gem_tasks` does not run it ([Rakefile](https://github.com/troessner/reek/blob/v6.6.0/Rakefile)); no release gate over the documentation was found.

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fails. A comment above a module or method containing `:reek:` and a smell type, such as `# :reek:UtilityFunction`, disables that detector for it ([smell suppression](https://github.com/troessner/reek/blob/v6.6.0/docs/Smell-Suppression.md)); the comment is parsed by [`code_comment.rb`](https://github.com/troessner/reek/blob/v6.6.0/lib/reek/code_comment.rb) on every run, no option refuses it, no detector reports it, and a project cannot write a detector that would. A file carrying it printed nothing and exited 0 (ran). The baseline is no better seen: `reek --todo` writes `.reek.yml` with an `exclude` entry for each smelly context, Reek loads that file from the working directory on every run, and the run then printed nothing and exited 0; `--show-configuration-path` names the file but not what it excludes (ran). No reason is asked for on a comment ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)).

A file Reek cannot parse exits 0. `reek broken.rb` printed a banner saying the source "cannot be processed by Reek due to a syntax error" with a backtrace, and exited 0 (ran). Under reading 9 this is not graded under [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran), but a defence routed through Reek stops defending that file without failing the run. `reek --smell NoSuchSmell r.rb` also exited 0 with no output (ran), so a misspelt smell type in a red proof looks like a pass.

Readiness is 🔴 because no bespoke rule can be written. The detector grade is 🔴 because [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) and [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fail, both structural under reading 1; [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) and [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) to [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fail too. Reek declares no version of this document.

## Notes for a practitioner

Reek is worth running for its design smells, but it cannot hold a project's own defence: put that in RuboCop as a cop, and use Reek alongside it. Treat a smell type as fixed to its class, since a rename upstream renames it. Look a smell type up in the installed `lib/reek/code_climate/code_climate_configuration.yml` rather than following the printed link, which needs the network and a re-spelt name. Search the code for `:reek:` outside Reek, in the build, if the project forbids suppressions, and keep the `.reek.yml` written by `--todo` under review, since Reek reports neither. Check the parse separately, with `ruby -c` or RuboCop's `Lint/Syntax`, because a file Reek cannot parse exits 0, and check the spelling of the smell type given to `--smell`, because a wrong one exits 0 too.
