# Pylint

{% include tool-grades.html %}

Pylint is the oldest general-purpose Python linter still in wide use, built on the astroid AST library and organised as a set of checkers that emit messages with numeric identifiers such as `W0611` and symbolic names such as `unused-import`. In a pipeline it is slower than Ruff and is kept for its deeper inference and, above all, for the fact that a project can write its own checkers and register them alongside the bundled ones.

## How it is conformant

Pylint is the strongest Python tool on section [4](../DETECTOR-SPEC.md#4-authoring-rules). The [custom checker guide](https://pylint.readthedocs.io/en/stable/development_guide/how_tos/custom_checkers.html) shows a project subclassing `BaseChecker`, declaring a `msgs` dictionary that maps a chosen identifier and symbolic name to the message text and description, and enabling it through `load-plugins` in the configuration ([4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)). The identifier is chosen once by the rule author and is not derived from the class or file name, and it is printed with every message in the default output and in the JSON reporter ([4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding)). The same guide describes `CheckerTestCase` with `assertAddsMessages` for proving a checker against a fixture without running the project's tests ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)). The row rests on that harness rather than on `--disable=all --enable=<symbol>` ([running Pylint](https://pylint.readthedocs.io/en/stable/user_guide/usage/run.html)), which runs only the checkers with an enabled message but every check within them: at 4.1.2, with two project checkers that each wrote a file when they ran, enabling a message of one left the other's file unwritten, whilst the selected checker's other message was still raised and only its printing suppressed (ran), a print filter for a checker with several messages (reading 21). Locally, `pylint mymodule.py` runs on a single file, which meets [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) and [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file), and every message runs locally with no hosted service ([5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)). By default every message is printed with its identifier in the command's output. `pylint --help-msg=<msg-id>`, a command Pylint ships, takes either printed form, `W0611` or `unused-import`, and prints the message's description from the installed package, offline ([6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access)); the descriptions are often a line or two, which reading 12 accepts. All 444 messages of the core checkers and the bundled extensions have a non-empty description (counted at 4.1.2), and a bundled extension's message resolves wherever the configuration that loads it is read: `--help-msg=W9015` answered "No such message" with no configuration and printed `missing-param-doc`'s description beside a `.pylintrc` loading `pylint.extensions.docparams` (ran). Because each description lives in its checker's `msgs` entry and the command presents it, the documentation ships with the rule at the same version ([6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together)). The same command resolves a project checker's identifier too, which goes further than [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) asks.

## How it is not conformant

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is partial. No option switches the inline `# pylint: disable=` route off ([message control](https://pylint.readthedocs.io/en/stable/user_guide/usage/run.html)), so it must be detectable, and every detection route Pylint offers can be silenced by the route itself. The guide documents raw and token checkers that see comments, so a project can write a checker that fails on any `# pylint:` comment: at 4.1.2 such a checker (`proj-no-disable`, `W9902`) reported `import os  # pylint: disable=unused-import` and the run exited 4, but it reported nothing and the run exited 0 when the same comment also named `proj-no-disable`, or when an earlier line carried `# pylint: disable=proj-no-disable`. The bundled [`locally-disabled`](https://pylint.readthedocs.io/en/stable/user_guide/messages/information/locally-disabled.html) (`I0011`) and [`suppressed-message`](https://pylint.readthedocs.io/en/stable/user_guide/messages/information/suppressed-message.html) (`I0020`) messages are a documented mechanical check over every disable comment that does suppress something: at 4.1.2 both were printed for a `# pylint: disable=unused-import`, and because they are informational the run exited 0 until `--fail-on=locally-disabled,suppressed-message` was added, when it exited 1. But a line `# pylint: disable=locally-disabled,suppressed-message` above the disable silenced both, and the same run exited 0. `useless-suppression` reports only a disable that no longer suppresses anything. Every detection of the route, the project's checker and the bundled messages alike, is silenced by the route naming it, and Pylint documents no way to make a message unsuppressible, so the route is detected only in part (reading 19), and no route being wholly unseen, the row is Partial (reading 16). A `# pylint: skip-file` is caught: it printed `file-ignored` (`I0013`), and `--fail-on=file-ignored` exited 1.

Clause [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) is partial: the documented `--output` option, "Specify an output file" ([all options](https://pylint.readthedocs.io/en/stable/user_guide/configuration/all-options.html#output-option)), writes every message to the file and leaves the command's own output empty, with no count and no location (ran at 4.1.2: standard output and standard error were empty and the run exited 20), which is Partial under reading 8. The default output meets the clause.

The two SHOULDs are not met in full. Clause [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) asks for "a Rule over the Rules, failing any Rule that reports without a stable Identifier", and there is no such rule. `MessageDefinition.check_msgid` raises `InvalidMessageError` when a checker registers an id that is not five characters with a valid type letter ([`message_definition.py`](https://github.com/pylint-dev/pylint/blob/v4.1.2/pylint/message/message_definition.py#L56)), and at 4.1.2 a probe checker declaring `proj1` stopped the run with that error. That refusal at load enforces the presence and form of the identifier, though not its stability, so [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is partial. Nor is a reason required: `# pylint: disable=<symbol>` suppresses any message inline with no reason asked for and no option that would demand one ([message control](https://pylint.readthedocs.io/en/stable/user_guide/usage/run.html)) ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)). Pylint runs its own checks on its own source, but no release-blocking audit that every bundled message resolves is published ([6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation), not verified). Pylint declares no version of this document, so its grades rest on the evidence above and not on a declaration. The detector grade is 🟡: no structural clause fails, and [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) and [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) are partial (reading 1). Readiness is 🟢.

## Notes for a practitioner

Write the class as a checker under `load-plugins`, choose a message id in the custom range the guide recommends, prove it with `CheckerTestCase` and then with `--disable=all --enable=<symbol>` on the originating file. Forbid `# pylint: disable` by enabling `locally-disabled` and `suppressed-message` with `--fail-on=locally-disabled,suppressed-message` in the enforced invocation, or with a small token checker of the project's own, since Pylint will not do so unasked; a disable that names `locally-disabled`, `suppressed-message` or the project's checker hides it, so back either with a text search outside Pylint for comments naming them. Leave `--output` out of the enforced invocation, or print the file afterwards, since the command itself then prints nothing. Keep every configuration-level `disable=` entry beside a comment naming the hazard and scope.
