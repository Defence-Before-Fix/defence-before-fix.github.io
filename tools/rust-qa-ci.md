# rust-qa-ci

{% include tool-grades.html %}

rust-qa-ci is one QA entry point for a Rust workspace, the `rust-qa` binary ([repository](https://github.com/LongTermSupport/rust-qa-ci)). `rust-qa run` formats, then runs its detectors (its own record, suppression, summary and documentation checks, ast-grep, Clippy and Dylint), then its runners (cargo-deny, cargo-audit, cargo-machete, the tests, coverage and mutation testing), and it ships a Dylint library and an ast-grep pack of its own. Around them it adds `rust-qa rule-doc` to resolve a printed identifier offline, `rust-qa rules` to list the active defences from configuration, a project record, `qa/record.toml` by default, whose every entry must be justified, attributed and dated, and a generated summary for an agent's file. Release 0.4.0 lets one repository host its whole QA through project stages, commands of any kind the project declares.

Every grade below rests on runs of the tag. The binary was installed as its README documents, `cargo install --locked --git https://github.com/LongTermSupport/rust-qa-ci --tag v0.4.0 rust-qa`, with the pinned tools from `scripts/install-tools.sh` (Rust 1.99.0, cargo-dylint 6.1.0, ast-grep 0.45.3, cargo-deny 0.20.2), into a probe workspace that loads the bundled Dylint library from the tag by git, as the README shows, beside a library of the probe's own. Detector conformance is graded on the detectors the toolchain routes a defence through, each with the wrapping around it (reading 3). Toolchain conformance grades what a consuming project installs. Project conformance grades the repository as a project following the method with the toolchain it ships.

## Tools it bundles

`rust-qa tools` lists the catalogue; each tool is selected with `-t <name>`, and every lane's failures print `= doc: rust-qa rule-doc <id>` under the finding.

- **fmt**: `cargo fmt`, fixing locally and checking with `--no-fix`. A formatter; not a host.
- **record, suppression, summary, docs**: checks of the toolchain's own, printing `rqaci.record.*`, `rqaci.suppression.*`, `rqaci.summary.stale` and `rqaci.docs.*`, each with a bundled page. Not hosts.
- **ast-grep**: hosts the project's own syntactic rules from `sgconfig.yml`, runs `ast-grep test` over them, and requires a test case of each project rule at error severity (`rqaci.rules.untested`); it also runs the bundled `rqaci.ast.*` pack. Wrapped by `rule-doc`, `rules`, `docs-check`, the record and the suppression scan. A detector a defence is routed through ([the ast-grep page](ast-grep.md)).
- **clippy**: Clippy with `-D warnings` over the Cargo `[lints]` tables, whose entries `rust-qa rules` lists as defences, with bundled pages for `warnings` and the Clippy groups and `cargo clippy --explain` for each lint. A fixed catalogue that can host no rule of the project's own, routed defences all the same ([the Clippy page](clippy.md)).
- **dylint**: hosts the project's own type-aware lints from `[workspace.metadata.dylint]`, blocking on every finding of a configured library's lint at any level unless the record covers it; the bundled `rqaci_lints` library adds `rqaci_sensitive_debug_derive` and `rqaci_suppression_generated`. Wrapped by all of the toolchain's mechanisms ([the Dylint page](dylint.md)).
- **deny, audit, machete, test, coverage, mutants**: cargo-deny ([page](cargo-deny.md)), cargo-audit, cargo-machete ([page](cargo-machete.md)), nextest with doctests, cargo-llvm-cov and cargo-mutants ([page](cargo-mutants.md)), placed by the toolchain among the runners and listed under one umbrella identifier each. Not hosts of a project's rule.
- **Project stages**: commands the project declares in `qa/rust-qa.toml`, in any phase. An installation with nothing built around it has none, so none is graded here.

## How it is conformant

Bespoke rules enter two ways, both documented in the README's "Writing rules": a Dylint library listed in `[workspace.metadata.dylint]`, and ast-grep rules in the directories `sgconfig.yml` names. In the probe, a lint `proj_no_sleep` was added the documented way: a `dylint_testing` fixture calling `std::thread::sleep` was written first and `cargo test` in the library failed with the expected warning missing from the diff, then the lint was declared and registered and the same test passed (ran). Under `rust-qa run` the finding printed rustc's own rendering, `` `#[warn(proj_no_sleep)]` on by default ``, then `= gate: blocking; a dylint finding fails the gate unless the project record covers it` and `= doc: rust-qa rule-doc proj_no_sleep`, and the run failed, though the lint is declared at warn (ran). A project ast-grep rule `proj.no-unwrap` printed `error[proj.no-unwrap]` with the same `= doc:` line, and `ast-grep test` ran its `valid` and `invalid` cases within the lane (ran). For both forms there is a harness that runs the rule alone, `dylint_testing` and `ast-grep test`, and the identifier the author chose is printed unaltered on every finding, so for the rules a project writes, detector clauses [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) to [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) hold. `rust-qa run` needs no service ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure)), its summary names each tool passed or failed with the findings above it ([5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran)), and CI runs the same command ([5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)).

`rust-qa rule-doc <id>` resolves an identifier exactly as printed, offline. Inside `unshare -rn`, with no route out, it printed the page for `rqaci.record.invalid`, the bundled pages for `rqaci_sensitive_debug_derive` and `rqaci.ast.hardcoded-temp-path`, the project's own page for `proj_no_sleep` from `docs/defences/`, Clippy's full text for `clippy::len_zero` through `cargo clippy --explain`, and for the rustc lint `unused_variables` the one-line description from `rustc -W help`, `detect variables which are not used in any way`, since the minimal profile installs no `rust-docs` (all ran; [`docs.rs` at v0.4.0](https://github.com/LongTermSupport/rust-qa-ci/blob/v0.4.0/crates/rust-qa/src/docs.rs)). That line is short and its brevity is recorded here, but it is documentation reached by the identifier as printed (reading 12). `docs_dir`, `docs/defences` by default, is the place a rule author's page goes, and the docs lane failed `proj_no_raw_sql` as `rqaci.docs.dangling` until its page existed (ran).

On the toolchain document, `rust-qa rules` is derived from the configuration in force: the lint added above appeared on the next listing with no other edit, as did the ast-grep rule, beside the bundled defences and then the project record (ran; toolchain [5.2](../TOOLING-SPEC.md#52-the-listing-must-be-derived-from-the-active-configuration), [5.3](../TOOLING-SPEC.md#53-a-projects-own-defences-must-appear-in-the-listing-alongside-bundled-ones), [6.3](../TOOLING-SPEC.md#63-the-project-record-must-be-enumerable-by-the-same-means-as-the-defences)). The record is `qa/record.toml`, loaded by the record and suppression lanes on every run ([6.1](../TOOLING-SPEC.md#61-the-toolchain-must-define-a-location-for-the-project-record-and-must-read-it-itself)). An entry whose justification was empty, `legacy`, `needed for now` or `TODO: fix` failed as `rqaci.record.invalid`, and one naming why the expectation was safe passed; each names one path, and a glob needs `policy = true` (ran; [6.2](../TOOLING-SPEC.md#62-every-exception-in-the-project-record-must-carry-a-written-justification-that-names-the-hazard-and-the-scope-and-the-toolchain-must-reject-a-generic-one)). Beyond the specification, budgets, a signed ratchet on the record's size, review dates and trust tiers by the model that wrote an entry keep the record small; adding an entry failed `rqaci.record.ratchet` until the ceiling was raised under a fresh signature (ran). The README's "Configuration" states every default ([6.4](../TOOLING-SPEC.md#64-the-toolchain-should-state-its-own-defaults-for-anything-the-method-leaves-to-the-project)). `rust-qa summary` writes one line per defence, with its identifier, level, description and `rust-qa rule-doc` route, into a delimited region of the file `[summary] file` names, and a stale region fails `rqaci.summary.stale` (ran). Its own bundled pages are held by tests: every page under `docs/rules/` is bundled, starts with its identifier and has a "How to fix correctly" section, every built-in identifier and every pack rule has one, and the docs lane of the self-gate fails a listed identifier with none ([`docs_test.rs`](https://github.com/LongTermSupport/rust-qa-ci/blob/v0.4.0/crates/rust-qa/tests/docs_test.rs), [`builtin_test.rs`](https://github.com/LongTermSupport/rust-qa-ci/blob/v0.4.0/crates/rust-qa/tests/builtin_test.rs), [`ast_grep_test.rs`](https://github.com/LongTermSupport/rust-qa-ci/blob/v0.4.0/crates/rust-qa/tests/ast_grep_test.rs); [8.1](../TOOLING-SPEC.md#81-a-shipped-toolchain-must-fail-its-own-release-if-a-bundled-defence-lacks-resolvable-documentation)). The self-gate job runs `rust-qa run --ci` on the repository with the bundled library loaded by path, and the library checked as a further workspace ([`ci.yml`](https://github.com/LongTermSupport/rust-qa-ci/blob/v0.4.0/.github/workflows/ci.yml); [8.2](../TOOLING-SPEC.md#82-a-shipped-toolchain-must-run-its-own-bundled-defences-on-its-own-source)); its detector lanes passed on the tag here (ran), and the workflow passed on the tagged commit. `[workspace.metadata.defence-before-fix]` in `Cargo.toml` declares method 1.1.0, detector 1.0.0 and toolchain 0.2.0 at `level = "partial"` with four gaps, and `docs/CONFORMANCE.md` sets out the evidence ([9.2](../TOOLING-SPEC.md#92-the-declaration-is-the-claim-and-the-known-gap-record-not-a-condition-of-conformance)).

## How it is not conformant

**Clippy is routed defences it cannot host.** Under reading 3 the detector column takes, clause by clause, the lowest result over Dylint, ast-grep and Clippy, each as wrapped. The toolchain lists every `[lints]` entry as a defence (`clippy::len_zero  clippy  deny  Cargo.toml:16`), resolves it and gates on it, and its own gap record says so: "Clippy is routed through a wrapper ... bespoke rules are authored with dylint, not Clippy itself". Clippy can host no rule of the project's own, and toolchain clause [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification) says such a detector "cannot be wrapped into Conformance, and no Defence is routed through it". Detector [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) is No for Clippy as wrapped, structural under reading 1, and the detector grade is red, though a practitioner writing a defence always has Dylint or ast-grep to write it in; toolchain [4.1](../TOOLING-SPEC.md#41-every-detector-the-toolchain-routes-a-defence-through-must-conform-to-the-detector-specification) fails on the same fact. Clippy's own gaps then carry into the column. The wrapping adds no single-lint run: `rust-qa run -t clippy` runs every lint, and Clippy's level flags only choose what is emitted (detector [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) Partial, reading 21). In the default run, the lane prints Clippy's human output as it comes: a probe with `len_zero = "deny"` in `[lints.clippy]` printed `` requested on the command line with `-D clippy::len-zero` `` on the first finding, a hyphenated form, nothing on the second, and `` `-D clippy::print-literal` implied by `-D warnings` `` for another lint (ran). Under `-p` the lane reads JSON and prints `= doc: rust-qa rule-doc clippy::len_zero` after every finding, unaltered (ran; [`tools.rs` at v0.4.0](https://github.com/LongTermSupport/rust-qa-ci/blob/v0.4.0/crates/rust-qa/src/tools.rs)), so the identifier is whole on every finding only under a flag: detector [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) Partial (readings 5 and 6), and toolchain [4.4](../TOOLING-SPEC.md#44-the-toolchains-own-invocation-must-satisfy-the-detector-specifications-reporting-clauses-for-every-defence-it-routes), which asks the entry point to print every identifier unaltered, is Partial with it.

**One file is reached by filtering a crate.** `rust-qa run -p src/main.rs` ran `cargo clippy -p probe` and `cargo dylint --all -p probe` over the whole package and kept the diagnostics whose span lies in the named path: a Dylint finding in `src/other.rs` was not printed for `-p src/main.rs` and was for `-p src/other.rs`, whilst ast-grep was given the file itself (ran). The command names the file but reaches it by setting aside the findings on every other file, so detector [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file) is Partial for Clippy and Dylint as wrapped (reading 22), and toolchain [4.4](../TOOLING-SPEC.md#44-the-toolchains-own-invocation-must-satisfy-the-detector-specifications-reporting-clauses-for-every-defence-it-routes) is Partial on it as well.

**Printed pointers that resolve nothing.** Every Dylint run, and a Clippy run under `-p`, follows a compiler error with a pointer to the toolchain's resolver. A type error printed `error[E0308]: mismatched types` and then `= doc: rust-qa rule-doc E0308`, and `rust-qa rule-doc E0308` answered `no documentation for E0308 (dangling identifier)` with exit 1, online and with no network (ran). The resolver tries project pages, stages, bundled pages, `clippy::` names and rustc lint names, and nothing else ([`docs.rs`](https://github.com/LongTermSupport/rust-qa-ci/blob/v0.4.0/crates/rust-qa/src/docs.rs)); `rustc --explain E0308` would resolve the code, but the scoped and Dylint output prints the toolchain's pointer in its place, since the line naming `rustc --explain` is a separate message the lane does not keep. ast-grep's own `unused-suppression`, printed as `warning[unused-suppression]` with `= doc: rust-qa rule-doc unused-suppression` when an ignore in Rust named a project rule that matched nothing, dangled the same way, and so did cargo-deny's `unlicensed`, which the deny lane printed as `error[unlicensed]` beneath the failure line telling the reader to run `rust-qa rule-doc <id>` (all ran). Reading 27 counts every identifier the command prints, so `rust-qa rule-doc` resolves some printed identifiers and not others: detector [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) and [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) are Partial (readings 14 and 27), and detector [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) is No, since one identifier that does not resolve fails it. Detector [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) is No under reading 28, since `E0308` and `unused-suppression` land on no page through the pointer the command prints, and no test walks the codes the compiler or ast-grep can print; this is the dangling reference detector [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) names as the failure to guard against. Toolchain [4.2](../TOOLING-SPEC.md#42-the-toolchain-must-resolve-every-identifier-a-defence-it-routes-can-print-from-the-installed-copy-without-network-access) fails on the same runs, and on a project's own rule as well: an ast-grep rule file with no `id`, which ast-grep runs under its file name, printed `error[noid]` with `= doc: rust-qa rule-doc noid`, was not listed, was not required to have a page or a test, and resolved to nothing (ran). The rustc lints resolve, but to `rustc -W help`'s one line, which states no correct construction, as the gap record notes. Toolchain [8.1](../TOOLING-SPEC.md#81-a-shipped-toolchain-must-fail-its-own-release-if-a-bundled-defence-lacks-resolvable-documentation) holds, since the identifiers that dangle belong to the compiler's, ast-grep's and cargo-deny's native catalogues, which that clause leaves out.

**Three suppression routes the scan does not read.** The suppression scan parses `.rs` files and four configuration files, and nothing else ([`suppression.rs`](https://github.com/LongTermSupport/rust-qa-ci/blob/v0.4.0/crates/rust-qa/src/suppression.rs)). ## Notes for a practitioner

Write a defence as a Dylint lint, with a project prefix and a page in `docs/defences/` that says how to fix correctly, prove it with `dylint_testing` against a fixture before the lint exists, and check that `rust-qa rules` lists it; an ast-grep rule serves where syntax suffices, but always give it an `id`, since one without runs under its file name and passes every check. Run one file with `rust-qa run -p <file>`, which also puts the lint name on every Clippy finding; in a full run, read the name from the note on the first finding or from `rust-qa rule-doc`. Prefer `#[expect(..., reason = "...")]` with a record entry to `#[allow]`, which fails `rqaci.suppression.allow` even when recorded. Search for `#[automatically_derived]` outside derive output, for lint attributes in files brought in with `include!` that do not end in `.rs`, and for `ast-grep-ignore` in any other language's files, since the gate does not see them. A `rule-doc` pointer under a compiler error leads nowhere; use `rustc --explain` for an `E` code. Name the bundled library by path, or set `CARGO_NET_OFFLINE=true`, where the listing must work with no network.
