# Standard Ruby

{% include tool-grades.html %}

Standard Ruby, the `standard` gem and its `standardrb` command, is a linter and formatter built on RuboCop: it pins RuboCop 1.91.0, rubocop-performance and its own `standard-custom` cops to one configuration that a project cannot change, and runs them through RuboCop's runner with a formatter of its own. In a pipeline it takes RuboCop's place as the Ruby lint step for a project that wants no style debate, and it is also where a project's own cop runs, since Standard loads additional cops beside its fixed set.

## How it is conformant

A project cop is a RuboCop cop, a subclass of `RuboCop::Cop::Base`, loaded through either of Standard's two extension mechanisms: a `lint_roller` plugin listed under `plugins:`, or a RuboCop configuration file listed under `extend_config:` in `.standard.yml`. Neither can change Standard's own rules, but both "can define, require, and configure _additional_ RuboCop rules" ([README, Extending Standard](https://github.com/standardrb/standard/blob/v1.57.0/README.md#extending-standard)). A probe cop `Proj/NoSleep`, required from an `extend_config` file, reported `s.rb:3:1: Proj/NoSleep: do not call sleep.` beside the bundled `Lint/UselessAssignment` and `Style/StringLiterals` at version 1.57.0 (4.1, ran). Standard forwards "most CLI arguments to RuboCop" (`standardrb --help`), and `standardrb --only Proj/NoSleep s.rb` printed that one offence with every other cop silent (4.2, ran, reading 4). It runs locally on a single file with no service and no licence tier (5.1, 5.2, 5.4).

The cop name is printed unaltered in Standard's default output and in every RuboCop format given to `--format`: `simple`, `clang`, `progress`, `emacs`, `tap`, `markdown`, `html`, `json` (as `cop_name`), `junit`, `sarif` (as `ruleId`), `github` and `offenses`; `worst` and `files` print no individual offence (ran).

The inline directives, `# standard:disable` and `# rubocop:disable` in their line, range and `all` forms ([README, Ignoring errors](https://github.com/standardrb/standard/blob/v1.57.0/README.md#ignoring-errors)), are switched off by RuboCop's `--ignore-disable-comments`, which Standard forwards: on a file with four `sleep` calls, three of them under a directive naming the cop or `all`, the plain run reported one and the run with the flag reported all four (7.1, ran). The generated `.standard_todo.yml` baseline is read on every run unless `--generate-todo` is given, and Standard's formatter then prints `WARNING: this project is being migrated to standard gradually via` the file's path `and is ignoring these files:` with each file listed ([`formatter.rb`](https://github.com/standardrb/standard/blob/v1.57.0/lib/standard/formatter.rb), ran), so the route is detectable under reading 18. The `ignore:` list in `.standard.yml` is the project's own configuration, which it can leave empty.

## How it is not conformant

Clause 4.3 fails, as it does for RuboCop. A cop's name is RuboCop's `Badge`, built from the Ruby module and class name ([`badge.rb`](https://github.com/rubocop/rubocop/blob/v1.91.0/lib/rubocop/cop/badge.rb)), so `RuboCop::Cop::Proj::NoSleep` prints `Proj/NoSleep` and renaming the class renames the identifier, which is the derivation from a class name that 4.3 rules out (reading 5). No cop, bundled or the project's, can carry an identifier chosen in a field of its own. There is no rule over the rules (4.4).

Clause 5.3 is partial (reading 8). `standardrb -f json -o out.json s.rb` wrote the findings to `out.json` and printed nothing at all on the console, exit 1 (ran); giving a second `-f` with no `-o` after it, as in `-f json -o out.json -f simple`, kept a report on the console as well. `-o` alone, without `-f`, wrote no file and left the default report on the console (ran), because Standard always installs its own formatter first ([`merges_settings.rb`](https://github.com/standardrb/standard/blob/v1.57.0/lib/standard/merges_settings.rb)).

Clauses 6.1 to 6.3 fail. Standard ships no lookup: its command always runs RuboCop's lint runner, so `standardrb --show-cops Lint/UselessAssignment` took the name for a file path and failed with `No such file or directory`, and `--show-docs-url` was ignored and the run linted the directory (ran, [`merges_settings.rb`](https://github.com/standardrb/standard/blob/v1.57.0/lib/standard/merges_settings.rb), [`runners/rubocop.rb`](https://github.com/standardrb/standard/blob/v1.57.0/lib/standard/runners/rubocop.rb)). The default output prints no documentation address. The `rubocop` command installed as a dependency does resolve RuboCop's own cops offline, `rubocop --show-cops Lint/UselessAssignment` printing its description with the network removed (ran under `unshare -rn`), but it is RuboCop's command, not one Standard ships (reading 10). Even that route leaves a bundled name unresolved: Standard's own `Standard/BlockSingleLineBraces`, from `standard-custom` 1.0.2, has no description anywhere in the installed gems, and `rubocop --plugin standard-custom --show-cops Standard/BlockSingleLineBraces` printed only `Enabled: true` (ran, [`standard-custom` configuration](https://github.com/standardrb/standard-custom/blob/v1.0.2/config/base.yml)). One such name fails 6.3, and no check over the bundled names exists (6.4).

Clause 7.2 fails. Standard's [`config/base.yml`](https://github.com/standardrb/standard/blob/v1.57.0/config/base.yml) sets `Style/DisableCopsWithinSourceCodeDirective`, the cop RuboCop offers to require a reason on a directive, and `Lint/RedundantCopDisableDirective` to `Enabled: false`, and an extension "can't change" a rule Standard configures. An `extend_config` file enabling both, with `AllowWithReason: true`, still loaded the project cop but reported neither a directive without a reason nor a redundant one (ran).

Readiness is 🟡 rather than 🟢 because the printed name, though always present, is derived from the class; the workaround is to choose the class and module name as carefully as an identifier and never rename them. The detector grade is 🔴 because 4.3 fails structurally under reading 1: no cop can carry an identifier other than one built from its class. Clauses 5.3, 6.1, 6.2 and 6.3 are also not met. Standard declares no version of this document.

## Notes for a practitioner

Write the defence as a RuboCop cop in a department named for the project, load it through `extend_config`, choose its class and module name as carefully as an identifier, because they are one, and never rename them. Prove it with RuboCop's `expect_offense` and then with `standardrb --only <Department/Name>` on the originating file. Run `standardrb --ignore-disable-comments` in the project's audit, since Standard will not let a project require reasons on directives or report redundant ones; a project that needs reasoned suppressions has to check the comments outside Standard. Read the todo warning at the top of each run as the list of files still excused, and keep `-o` out of the enforced invocation unless a second `-f` keeps the report on the console. Look up a RuboCop cop with the installed `rubocop --show-cops <name>`, remembering that Standard's own `Standard/` cops have no description there.
