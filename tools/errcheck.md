# errcheck

{% include tool-grades.html %}

errcheck reports calls whose returned error is neither assigned nor explicitly discarded, "silently ignored errors in Go code" ([README at v1.20.0](https://github.com/kisielk/errcheck/blob/v1.20.0/README.md)). It is one of the oldest Go linters and one of golangci-lint's default set, and most projects run it there; on its own it is the `errcheck` command. It has one check, widened by `-blank` and `-asserts` and narrowed by exclusion lists, and no way to add another, so it cannot host a bespoke defence.

## How it is conformant

The reporting clauses are met. `errcheck` runs locally on packages or on a single file, `errcheck ./b.go`, and prints each finding to the command's own output as the position, a tab and the call, `b.go:6:11: os.Remove("d")`, exiting 1 (ran under Go 1.26.8), which meets [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) to [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally); there is no option that writes the findings elsewhere. Graded on its one check, [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is met: a run over a fixture is that check alone, with nothing else to obscure it and no test suite run (ran).

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) holds. errcheck has no inline suppression route: a call carrying `//nolint:errcheck // reason` was reported like any other (ran), and assigning the error to `_` is a change to the code, which `-blank` reports in turn (ran). The exclude file is a route under reading 29, a file of entries each naming a function whose unchecked error is accepted ([README](https://github.com/kisielk/errcheck/blob/v1.20.0/README.md)), and so are `-ignorepkg` and the deprecated `-ignore`, which name packages and functions on the command line; each applies only where the command names it, so leaving it out is the setting that disables it (reading 17). So is `-ignoregenerated`, which skips a file headed `// Code generated ... DO NOT EDIT.` ([`errcheck.go`](https://github.com/kisielk/errcheck/blob/v1.20.0/errcheck/errcheck.go#L181)) and is off by default. The two exclusions errcheck applies by default, a built-in list of calls such as `(*bytes.Buffer).Write` ([`excludes.go`](https://github.com/kisielk/errcheck/blob/v1.20.0/errcheck/excludes.go)) and the whole `fmt` package, are switched off by the documented `-excludeonly`: a fixture with an unchecked `b.Write` and `fmt.Println` printed nothing by default and both findings with `-excludeonly` (ran). The one inline route, the generated-code header under `-ignoregenerated`, takes no reason, so [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) is not met.

## How it is not conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) fails: the README describes one check and flags that adjust what it reports, and the exported `go/analysis` analyser lets another driver run the same check, not add one. With no rules of the project's own, nothing enforces [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) on one, so [4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own) is No, not Not applicable (reading 7). Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) fails: a finding is a position and the source of the call, with no identifier of any kind, and plain text is the only format (ran). With nothing printed to key a lookup on, section [6](../DETECTOR-SPEC.md#6-resolving-an-identifier) has nothing to resolve, and [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) are No.

Three behaviours a defence routed through errcheck should know of. Release v1.20.0 does not run under Go 1.27.2: every run printed `internal error: package "os" without types was imported from "example.com/ec"` and exited 1, the code a finding gets, before checking anything (ran); under Go 1.26.8 the same fixtures ran. The fault is open upstream as [issue 289](https://github.com/kisielk/errcheck/issues/289). Under reading 9, a file that does not parse is reported, `error: failed to check packages: errors while loading package`, and exits 2, apart from a finding (ran). The README says `-verbose` shows "the resulting list of added excludes", but a run with `-exclude` and `-verbose` printed only `checking example.com/ec` (ran), so the run does not report what it excluded.

The detector grade is 🔴 on [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) and [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), both structural under reading 1, with [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) failing. Readiness is 🔴: no bespoke rules and no identifier on findings.

## Notes for a practitioner

errcheck is an off-the-shelf rule under method clause [3.2](../SPEC.md#32-build-the-net) for the class "an error return dropped on the floor", proven by a fixture with one unchecked call. Run it with `-blank` where an error assigned to `_` should need a reason, and with `-excludeonly` plus an exclude file of the project's own where the built-in list and the blanket `fmt` exclusion are not wanted, keeping each entry beside a comment that gives the reason. Pin Go 1.26 for it until a release fixes the Go 1.27.2 failure, and read the output rather than the exit code, since the internal error exits 1 like a finding. Through golangci-lint the same check prints `(errcheck)` after each finding and gains the `//nolint` route; see that page.
