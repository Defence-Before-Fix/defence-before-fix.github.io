# html-eslint

{% include tool-grades.html %}

html-eslint is a parser, an ESLint language and a set of sixty-six rules that let ESLint lint HTML files, and HTML inside JavaScript templates, with the same configuration, directives and formatters as the project's JavaScript. It is a plugin rather than a detector of its own, so it is graded here as rules hosted in ESLint, as [typescript-eslint](typescript-eslint.md) is: everything outside the rules and their documentation is ESLint's, set out on [the ESLint page](eslint.md). It was run with ESLint 10.12.0.

## How it is conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) is met. With `language: "@html-eslint/html"` in the flat configuration, a project rule written as an ordinary ESLint rule visits the HTML tree's nodes; a local plugin `proj` with a rule `no-b` on `Tag` nodes reported `use <strong>` beside `@html-eslint/no-duplicate-id` and `@html-eslint/require-img-alt` (ran at 0.66.1). Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is met by ESLint's `RuleTester` given the same language: it passed a valid and an invalid case for `proj/no-b` and for the bundled `require-img-alt`, and failed when a case that should be clean was not (ran). Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is met: each finding prints the rule name with the namespace its plugin was registered under, `proj/no-b` and `@html-eslint/require-img-alt`, unaltered in the default `stylish` output, in `json`, `json-with-metadata` and `html`, and as `ruleId` in SARIF through `@microsoft/eslint-formatter-sarif` (all ran).

Clauses [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file) and [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally) are met through ESLint: `eslint a.html` ran locally on one file, and every rule runs in the installed package. For [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable), ESLint's `noInlineConfig`, here `--no-inline-config`, made an `<!-- eslint-disable-next-line proj/no-b -- legacy -->` comment inert, so the finding it hid was printed (ran).

## How it is not conformant

Clause [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) is partial under reading 8, inherited from ESLint: `eslint -o o.txt a.html` wrote the findings to the file and printed nothing on standard output or standard error, with exit 1 (ran).

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) is partial, inherited from ESLint: after `eslint --suppress-all a.html` wrote `eslint-suppressions.json` with a count per rule, a plain `eslint a.html` read it and exited 0 on a file whose four findings had failed it before (ran). The file is read by default, nothing switches it off, and no rule can see it ([bulk suppressions](https://eslint.org/docs/latest/use/suppressions)).

Clause [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) is partial. Sixty-four of the sixty-six bundled rules carry a `meta.docs.url` of the form `https://html-eslint.org/docs/rules/<name>`, keyed on the rule name with the `@html-eslint/` namespace removed; the address with the printed identifier in it, `https://html-eslint.org/docs/rules/@html-eslint/require-img-alt`, returned HTTP 404, so under reading 11 it is keyed on something else. The other two, `indent` and `css-no-empty-blocks`, carry no URL at all (read from the installed package). A project rule's identifier is printed unaltered, which is what 6.1 asks for it. The pages are on the website and in the repository's [`docs/rules`](https://github.com/yeonjuan/html-eslint/tree/v0.66.1/docs/rules), and the package ships `lib`, `types` and a README, so nothing resolves offline ([6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) No) and the documentation does not ship with the rule ([6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) No). Whether a missing page blocks a release is not documented ([6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation), not verified).

There is no rule over the rules ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)), and an `eslint-disable` comment's reason after `--` is optional; nothing in html-eslint or ESLint requires it ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)).

An HTML file the parser could not make sense of, with an unclosed attribute and stray `<`, printed nothing and exited 0 (ran): the parser recovers rather than reporting a parse error, so a defence on that file says nothing (reading 9).

The detector grade is 🟡: no structural MUST fails, and [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran), [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation), [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) and [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) are the MUSTs that do not hold in full. Readiness is 🟢: bespoke rules, `RuleTester` and a printed stable identifier. html-eslint declares no version of this document.

## Notes for a practitioner

html-eslint is the way to put HTML classes in the same host, record and toolchain as the project's JavaScript. Write the rule as an ESLint rule on the html-eslint tree, prove it with `RuleTester` configured with the `@html-eslint/html` language, and give it a `meta.docs.url` in the project's own repository. A command-line `--rule` with `--no-config-lookup` cannot set the language, so an HTML file run that way was skipped with "File ignored because no matching configuration was supplied" (ran); prove on the command line with a one-rule configuration instead. Set `linterOptions.noInlineConfig`, keep `-o` out of the enforced invocation, and fail the project's own checks on an `eslint-suppressions.json`. Validate the markup with a conformance checker as well, since the parser accepts what it cannot parse.
