# knip

{% include tool-grades.html %}

knip finds what a JavaScript or TypeScript project no longer uses: files nothing imports, dependencies in `package.json` nothing references, imports of packages that are not listed, and exports, types, enum and namespace members nobody imports. It parses the project, resolves every import from the entry files that its plugins and configuration declare, and reports each kind of issue under a heading. In a pipeline it runs over the whole project, usually in CI and before a release, beside the linter rather than in place of it.

## How it is conformant

Clauses [5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure) and [5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally) are met: `knip` runs locally on the installed package, and a run with the network removed (`unshare -rn`) printed the same findings and exited 1, so nothing is held back for a service or licence tier. Clause [5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran) is met: every finding is printed in the command's own output, there is no option that writes the report elsewhere, and `--max-show-issues` trims a list only with a visible `…2 more items` (all ran at 6.41.0; [reporters](https://github.com/webpro-nl/knip/blob/knip@6.41.0/packages/docs/src/content/docs/features/reporters.md)).

## How it is not conformant

Clause [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) fails. The issue types are a fixed list in the binary, from `files` and `dependencies` to `exports`, `types` and `cycles` ([issue types](https://github.com/webpro-nl/knip/blob/knip@6.41.0/packages/docs/src/content/docs/reference/issue-types.md)), and the extension points do not add one: "Plugins provide Knip with entry files and dependencies it would be unable to find otherwise" ([writing a plugin](https://github.com/webpro-nl/knip/blob/knip@6.41.0/packages/docs/src/content/docs/writing-a-plugin/index.md)), and a preprocessor receives the finished results and "should return data in the same shape" ([reporters](https://github.com/webpro-nl/knip/blob/knip@6.41.0/packages/docs/src/content/docs/features/reporters.md)). A preprocessor that added issues under a new type `projNoX` ran without error, but no reporter printed them, and `--include projNoX` stopped with `Invalid issue type: projNoX` and exit 2 (ran). So the remaining clauses are graded on the bundled issue types.

Clause [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code) is partial under reading 4. `--include exports` ran only that type and printed only unused exports (ran), but not every type can be selected that way: `--include dependencies` takes `devDependencies` and `optionalPeerDependencies` with it, so those two can be run alone only through a `rules` configuration, and `--include nsExports` "adds them to the default report, rather than narrowing it" ([rules and filters](https://github.com/webpro-nl/knip/blob/knip@6.41.0/packages/docs/src/content/docs/features/rules-and-filters.md)), as a run confirmed by printing every default type beside it.

Clause [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding) is partial under reading 5. Each issue type has a key the maintainers assign, such as `exports`, which the CLI, the configuration and the JSON reporter all use, and the JSON reporter prints each finding under it unaltered. The default `symbols` reporter prints the type's title instead, `Unused exports`, as a heading, and so do `compact`, `markdown`, `disclosure`, `codeclimate` (`check_name`) and `github-actions` (`title=✂️ Knip / Unused exports`); SARIF prints `knip/exports`, a constant prefix that alters it under reading 6 (all ran). The key is therefore printed as it is only under `--reporter json`. There is no rule over the rules, since there are no project rules to check ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)).

Clause [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file) is partial. knip takes no file argument (`--help`, ran): it analyses a project or a workspace selected with `--workspace`, because whether an export is unused depends on every file that could import it. A configuration whose `project` pattern names one file, passed with `-c`, limited the export findings to that file, but the import graph is still walked from every entry file (ran).

Section [6](../DETECTOR-SPEC.md#6-resolving-an-identifier) fails for every issue type. No command explains one: `--help` lists the keys without a description. The installed package holds `dist`, two JSON schemas, `README.md` and `LICENSE`, and the README describes no issue type. The only documentation is the [issue types](https://github.com/webpro-nl/knip/blob/knip@6.41.0/packages/docs/src/content/docs/reference/issue-types.md) page on knip.dev, a table of title, description and key, which the SARIF reporter gives as `helpUri` for every rule alike; the identifier the same output prints is `knip/exports`, which the table does not carry, so under reading 11 nothing is keyed on the identifier as printed, and [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) is No. Nothing resolves offline ([6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) No, reading 14) and nothing ships ([6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) No). Version 6.41.0 was released with no issue type resolving, so no release gate of the kind [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation) asks for exists.

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fails under reading 16. The JSDoc tags `@public` and `@beta` stop an export being reported, and so does `@alias` for a duplicate ([JSDoc and TSDoc tags](https://github.com/webpro-nl/knip/blob/knip@6.41.0/packages/docs/src/content/docs/reference/jsdoc-tsdoc-tags.md)). The source treats them as "always ignored" ([`tag.ts`](https://github.com/webpro-nl/knip/blob/knip@6.41.0/packages/knip/src/util/tag.ts)): no setting turns them off, `--tags=+public`, the documented way to "focus on" tagged exports, printed nothing and exited 0 over a file with two unused exports tagged `@public` and `@beta`, and the tag hints report only a tag that is "no longer necessary because the export is actually used". With no project rules, nothing else can see them. The configuration routes, `ignore`, `ignoreFiles`, `ignoreDependencies`, `ignoreIssues`, `ignoreExportsUsedInFile`, `rules` set to `off` and `--exclude`, are configuration the project can simply not set ([configuration](https://github.com/webpro-nl/knip/blob/knip@6.41.0/packages/docs/src/content/docs/reference/configuration.md)), and an arbitrary tag such as `@lintignore` hides nothing until `--tags=-lintignore` asks it to (ran). No route asks for a reason ([7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason)).

A file knip cannot parse is skipped without a sign: a project whose only finding was in a file with a syntax error printed nothing and exited 0, and the same file once fixed printed its unused export and exited 1 (ran), so a defence routed through knip stops defending at the first syntax error (reading 9).

The detector grade is 🔴 because [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it) is No, which is structural under reading 1; [4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code), [4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), [5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file), [6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation) to [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) and [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) fail as well. Readiness is 🔴: there are no bespoke rules. knip declares no version of this document.

## Notes for a practitioner

knip is worth running for what it finds, but it cannot host a defence: write the class in ESLint or another host and keep knip as it ships. Run it from the project root with `--reporter json` where a script needs the issue type key, since the default output prints only the title. Forbid `@public`, `@beta` and `@alias` in the project's own checks if exports must not be exempted silently, because knip offers no switch for them and no listing of what they hid. knip respects `.gitignore` by default, so a project inside an ignored directory reports only its dependencies until `--no-gitignore` is given (ran). Run a type checker or the linter first, since a file knip cannot parse passes without a word.
