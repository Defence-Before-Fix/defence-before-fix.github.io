# StyleCop.Analyzers

{% include tool-grades.html %}

StyleCop.Analyzers is a set of style and consistency rules for C#, published as a NuGet analyser package and run inside an ordinary `dotnet build` on the [Roslyn host](roslyn-analyzers.md). Its rules carry identifiers such as `SA1003` and, for the optional rules, `SX1309`. The newest release on NuGet is a prerelease, [1.2.0-beta.556](https://www.nuget.org/packages/StyleCop.Analyzers/1.2.0-beta.556), which depends on `StyleCop.Analyzers.Unstable` version 1.2.0.556, where the analysers live; the last release without a prerelease label is 1.1.118. This page grades what the package adds to the host, as the [SonarAnalyzer.CSharp](sonaranalyzer-csharp.md) page does: a project's own rules are written for the host, not for this package.

## How it is conformant

The package runs where the build runs, with no service ([5.1](../DETECTOR-SPEC.md#51-the-detector-must-be-invocable-by-the-practitioner-locally-with-no-infrastructure)). Ran with the network removed: a one-file app with `#:package StyleCop.Analyzers@1.2.0-beta.556` printed `sc.cs(21,21): warning SA1003: Operator '+' should be followed by whitespace. (https://github.com/DotNetAnalyzers/StyleCopAnalyzers/blob/master/documentation/SA1003.md)` from `dotnet build sc.cs`, on one file with no project ([5.2](../DETECTOR-SPEC.md#52-the-detector-must-support-invocation-over-a-subset-at-minimum-a-single-file)), in the command's own output ([5.3](../DETECTOR-SPEC.md#53-the-result-must-reach-the-practitioner-in-the-output-of-the-command-they-ran)). Nothing in the package is held back for a service or licence tier ([5.4](../DETECTOR-SPEC.md#54-a-finding-must-not-be-reportable-only-through-a-hosted-service-licence-tier-or-ci-only-mode-the-practitioner-cannot-invoke-locally)). Identifiers are assigned once by the maintainers and printed unaltered on the console and as `ruleId` in the SARIF version 2.1.0 log written by `ErrorLog` ([4.3](../DETECTOR-SPEC.md#43-the-detector-must-allow-a-rule-to-carry-a-stable-identifier-and-must-print-it-with-every-finding), ran).

One rule runs alone against supplied code through the Roslyn test package ([4.2](../DETECTOR-SPEC.md#42-the-detector-must-provide-a-harness-that-runs-a-single-rule-against-supplied-code)). Each rule's documentation page names the analyser's type, as [`SA1003.md`](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/blob/1.2.0-beta.556/documentation/SA1003.md) gives `SA1003SymbolsMustBeSpacedCorrectly`. Ran: Microsoft.CodeAnalysis.CSharp.Analyzer.Testing version 1.1.4 ran that analyser alone against a source string marked `{|SA1003:+|}`, passing on the right span and failing on a wrong one. The analyser classes are internal, so the test loads the type by name from the assembly. Setting every other rule to `none` in `.editorconfig` is the other route, a configuration under reading 4.

Every identifier a finding can print is followed by an address keyed on the identifier exactly as printed, `documentation/<id>.md` in the project's repository ([6.1](../DETECTOR-SPEC.md#61-the-detector-must-provide-a-mechanism-that-resolves-a-printed-identifier-to-its-documentation)). Ran: 197 descriptors were loaded from the package, and all 196 that can be reported have a page under that name at the tag and on `master`. The 197th, `SA1119_p`, links to `SA1119.md`, but it is declared hidden and `NotConfigurable` ([source](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/blob/1.2.0-beta.556/StyleCop.Analyzers/StyleCop.Analyzers/MaintainabilityRules/SA1119StatementMustNotUseUnnecessaryParenthesis.cs)), so a build never prints it.

Clause [7.1](../DETECTOR-SPEC.md#71-a-detector-may-offer-an-inline-suppression-route-but-must-make-it-detectable-or-disableable) holds for each route that hides one of the package's findings. The package adds no route of its own. The host's routes are `#pragma warning disable`, the `SuppressMessage` attribute and the generated code header. Ran: in the SARIF log a pragma-hidden `SA1003` carried `"suppressionType": "Pragma Directive"` and an attribute-hidden one `SuppressMessageAttribute`. A one-file app whose first line was `// <auto-generated/>` reported nothing from the package, and `generated_code = false` in `.editorconfig` brought every `SA` finding back. Clause [7.2](../DETECTOR-SPEC.md#72-an-inline-suppression-route-should-require-a-written-reason) is met in part by `SA1404`, "Code analysis suppression should have justification" ([documentation](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/blob/1.2.0-beta.556/documentation/SA1404.md)). Ran: it fired on a bare `[SuppressMessage("StyleCop.CSharp.SpacingRules", "SA1003")]`. Its source also rejects the placeholder justification `<Pending>` ([source](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/blob/1.2.0-beta.556/StyleCop.Analyzers/StyleCop.Analyzers/MaintainabilityRules/SA1404CodeAnalysisSuppressionMustHaveJustification.cs)). Nothing asks a reason of a pragma.

## How it is not conformant

There are no bespoke rules ([4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it)). The [README at the tag](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/blob/1.2.0-beta.556/README.md) offers configuration of the existing rules through `stylecop.json` and `.editorconfig`, and no way to add a rule. A project's own rule is a Roslyn analyser that runs beside the package on the host. That is a structural failure, and it decides both grades. With no project rules there is no rule over the rules either ([4.4](../DETECTOR-SPEC.md#44-the-detector-should-enforce-43-with-a-rule-of-its-own)).

The documentation does not ship ([6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access), [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together)). Ran: the two packages hold the analyser and code fix assemblies, a licence and `THIRD-PARTY-NOTICES.txt`, and no page for any identifier. The printed address also points at the `master` branch, not at the release installed, so what it shows can change whilst the installed rule does not. For [6.4](../DETECTOR-SPEC.md#64-the-detector-should-fail-its-own-release-if-a-bundled-rule-lacks-resolvable-documentation), the suite's [`TestHelpLink`](https://github.com/DotNetAnalyzers/StyleCopAnalyzers/blob/1.2.0-beta.556/StyleCop.Analyzers/StyleCop.Analyzers.Test/AnalyzerConfigurationUnitTests.cs) fails when a descriptor's address is not `documentation/<id>.md` on `master`, but it never checks that the page exists. No.

The detector grade is 🔴: [4.1](../DETECTOR-SPEC.md#41-the-detector-must-support-bespoke-rules-written-by-the-project-that-runs-it), a structural MUST, is No. Clauses [6.2](../DETECTOR-SPEC.md#62-resolution-of-a-bundled-rules-identifier-must-work-from-the-installed-copy-without-network-access) and [6.3](../DETECTOR-SPEC.md#63-a-bundled-rules-documentation-must-ship-with-the-rule-at-a-version-tracked-together) fail as well. Readiness is 🔴, because there are no bespoke rules. A project that adopts the package keeps its defences in a Roslyn analyser of its own, graded on the [Roslyn host](roslyn-analyzers.md) page.

## Notes for a practitioner

Use the package for its catalogue and keep the bespoke defence in a Roslyn analyser of the project's own beside it. Turn `SA1404` into an error to make every `SuppressMessage` carry a justification. Set `generated_code = false` in `.editorconfig` for the project's own sources, so that a `<auto-generated/>` header does not hide a file from the package. If the documentation must be on disk, keep a copy of the `documentation/` directory at the tag of the release installed, since the printed address follows `master`. The analyser classes are internal: a test that runs one of them alone loads its type by the name its documentation page gives.
